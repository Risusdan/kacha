# storyboard：寫 edit.json

`work/edit.json` 是 Claude 唯一寫的資料檔。審閱頁（`pipeline review` 啟動的互動網頁，見 `reel` skill 第 8 節）也會寫它：使用者在頁面上切換剪掉或保留、拿掉或復原一句、改字幕的字，都直接存進這個檔案，每次都先通過 `validate`。使用者不讀它也不改它：他在頁面上點，或用中文講意見，你把意見改進這個檔案。審閱頁開著時，改之前先讀現在的檔案，在它上面改：頁面可能剛改過。

寫之前先讀兩份由 `pipeline` 指令產生的檔案（只讀，不改）：

- `work/transcript.json`：`sentences` 是腳本的每一句，有 `id`、`text`（字幕顯示的字）、`script_text`（腳本原文）、`display_source`（字幕的字從哪裡來：`"script"` 是腳本的字，`"asr"` 是辨識出來的字）、`spoken`（講者有沒有講）和 `ratio`（講的和腳本的吻合度）。
- `work/trim.json`：`trims` 是粗剪候選，有 `id`、`kind`、`sentence`（它歸在哪一句）、`text`（辨識文字）、`length`（字數：一個中文字或英文字算 1，一個字的猶豫聲不算）、`reason` 和 `suggest`（`cut` 或 `list`）。`kind` 有五種：`filler` 贅字、`repeat` 重複（包括口吃）、`retake`（NG 段，或措辭和腳本不同的改詞重講）、`extra` 腳本外的話、`pause` 停頓。

## 本期的鍵

本期的 `edit.json` 一定要有 `version`、`style`、`cuts`、`sentences`、`captions` 五個鍵，另外可以有 `notes`（註記，見下面「notes」）、`punch_in`（推近的倍數，見下面「punch_in：推近」）和 `scenes`（動畫卡片，見下面「scenes：動畫」）。多寫其他的鍵都會報錯；`broll`、`sfx`、`music` 屬於之後的期別，使用者現在要 B-roll（穿插在口播之間的補充畫面）、音效或背景音樂時，告訴他這個版本還沒有，不要寫進去。

範例（句子是編的）：

| 句子 | 內容 | 怎麼處理 |
|---|---|---|
| `s01` | 今天來聊三個省電的小技巧。 | `hook`，`main` |
| `s02` | 很多人以為關掉螢幕就會省電。 | `claim`，`main` |
| `s03` | 其實把亮度調低，一天可以多撐兩小時。 | `number`，`main` |
| `s04` | 當然，每支手機的情況不太一樣。 | `aside`，`sub` |
| `s05`、`s06` | 對了，昨天我去吃了一碗拉麵。味道真的不錯。 | 離題，整段移除 |

```json
{
  "version": 1,
  "style": "default",
  "cuts": {
    "accept": ["t01", "t02", "t04"],
    "reject": ["t03"],
    "extra": [{"from": "s05", "to": "s06", "reason": "離題"}]
  },
  "sentences": [
    {"id": "s01", "sem": "hook", "weight": "main"},
    {"id": "s02", "sem": "claim", "weight": "main"},
    {"id": "s03", "sem": "number", "weight": "main"},
    {"id": "s04", "sem": "aside", "weight": "sub"}
  ],
  "captions": {"mode": "line"}
}
```

- `version` 是 `1`，`style` 是 `"default"`。
- `cuts.extra` 可以省略；沒有要整段移除的句子時不寫，或寫 `[]`。
- `notes` 和 `captions.text` 的例子在後面各自的一節。

## cuts：每個粗剪候選都要決定

`trim.json` 的每個候選代號，都要出現在 `cuts.accept`（剪掉）或 `cuts.reject`（保留）其中一個，而且只出現一次。漏掉或兩邊都有，`validate` 都會報錯。

寫 `edit.json` 時，要使用者決定的候選先照下面的建議填好：關卡 1 上使用者回「可以」，或在審閱頁上同意，就是同意你填的，只有要改的才需要他回或在頁面上改（見 `reel` skill）。

`suggest` 是 `cut` 的候選放進 `accept`：

- 贅字（`filler`）；
- 重複（`repeat`），包括口吃，例如「我我我們」裡多出來的「我我」；
- NG 段（`retake`），包括 NG 之後說了「不對」「重來」「再來一次」這類口令的（`reason` 會寫是哪個口令）；
- 停頓（`pause`）。

`suggest` 是 `list` 的候選，程式只列出來，不自動剪，由你看辨識文字決定：

- **改詞重講**（`kind` 是 `retake`）：講者用不同的措辭把一句話講了一次，後來又照腳本講。讀候選的 `text`，和它相似的那句腳本（`sentence` 指的那一句，也可能是它前一句）的 `script_text`：
  - 只是那一句講到一半的舊版本，沒有那一句沒講到的內容：接受（剪掉）。
  - 有那一句沒講到的內容（新的數字、新的詞、新的重點）：拒絕（保留）。關卡 1 的訊息要說那是什麼內容。
- **腳本外的話**（`kind` 是 `extra`）：講者臨場加的話，腳本沒有。預設拒絕（保留）：臨場的話常是自然的口語，不要因為腳本沒寫就剪。明顯是口誤的接受（剪掉），例如講錯字之後的「糟糕，講錯了」、說到一半就放棄的幾個字，關卡 1 的訊息要說理由。`length` 在 3 以上的，關卡 1 會列出來問使用者；一兩個字的不問，在網頁的候選表，同樣的原則：明顯是口誤才接受。

腳本外的話和改詞重講裡一個字的猶豫聲（嗯、呃、欸、恩、額、誒；照字典斷詞時單獨成一個詞的才算，「感恩」的「恩」、「金額」的「額」不算），各自是一個 `filler` 候選，落在那一段的候選裡面，照預設接受。那一段接受時，它跟著被剪掉；那一段保留時，只有它被剪掉。

切點不在靜音裡的候選，剪下去可能切到字或有雜音。照上面的預設處理就好：接受而且在成品裡的，網頁會列在「其他要聽的地方」，使用者想聽可以聽，訊息裡不逐項問（見 `reel` skill）。

使用者改變決定時，把那個代號移到另一邊。

`trim` 重跑之後，候選代號是依位置編的，同一個代號可能指向不同的一段：要從新的 `trim.json` 重新決定每一個候選，不沿用舊的決定（見下面「寫完一定跑 validate」）。

### extra：整段移除句子

`cuts.extra` 的每一項是 `{"from": 句子代號, "to": 句子代號, "reason": 原因}`，把 `from` 到 `to`（含）的句子整段移除，字幕也跟著不出現。

- 只在使用者要求，或那幾句明顯離題時才用。不要因為你覺得某句多餘就自己移除。
- `reason` 一定要寫，用中文：分鏡稿會把它顯示在被移除的句子旁，使用者看得到。
- `from` 和 `to` 都必須是講者有講的句子，`from` 不能在 `to` 之後；兩個範圍不能重疊。
- 移除的每一句，都要從 `sentences` 拿掉那一筆，不然 `validate` 會報 `… is removed by cuts.extra`（見下面「sentences」）。
- 講者在一句前面講的腳本外的話或改詞重講，候選歸在那一句（`sentence` 是那一句的代號），卻在那一句的切點之前。移除的範圍從第一句的切點開始，剪不到它們，它們仍在成品裡。所以加好 `cuts.extra`、跑過 `validate` 和 `storyboard` 之後，看新的 `storyboard.md` 的候選表：範圍裡每一句的候選，種類是 `extra` 或 `retake`、沒標「不在成品裡」的，除非使用者說要留，也放進 `cuts.accept`，再跑一次 `validate` 和 `storyboard`；告訴使用者時用一句話說你把它們一起剪掉了。

## sentences：每個保留的句子一筆

每個「講者有講、而且沒被 `cuts.extra` 移除」的句子，都要在 `sentences` 裡有一筆，`id` 不重複。

- `spoken` 為 `false` 的句子（腳本有、講者沒講）不要寫，寫了會報錯。它不出字幕，分鏡稿標「沒講到」。
- 被 `cuts.extra` 移除的句子也不要寫。

每筆有 `sem`（語意標籤）和 `weight`。

### 12 個語意標籤

每句挑一個。拿不準時用 `claim`。

| `sem` | 意思 | 例句（編的） |
|---|---|---|
| `hook` | 開場鉤子 | 今天來聊三個省電的小技巧。 |
| `claim` | 觀點、主張 | 亮度才是最耗電的設定。 |
| `number` | 數字、數據 | 亮度調低，一天多撐兩小時。 |
| `list` | 條列 | 第一是亮度，第二是背景更新，第三是定位。 |
| `compare` | 對比 | 自動亮度比手動調整更省電。 |
| `steps` | 步驟、流程 | 先打開設定，再點顯示與亮度，最後把亮度拉到一半。 |
| `example` | 舉例、示範 | 像我自己的手機，亮度拉到一半就夠用了。 |
| `quote` | 引言 | 有人說：省電不是少用，是用得聰明。 |
| `define` | 名詞解釋 | 背景更新，就是應用程式在你沒開它的時候偷偷更新。 |
| `warning` | 提醒、注意 | 提醒你，調太低在太陽底下會看不清楚。 |
| `cta` | 號召（追蹤、留言） | 喜歡的話記得追蹤我。 |
| `aside` | 補充、過場 | 當然，每支手機的情況不太一樣。 |

### weight

- `main`：這句帶出新的重點、數字、步驟或對比。之後的期別會讓它帶出新的畫面元素。
- `sub`：陪襯句，承接、補充、重複前一句的意思，或只是過場。

`sem` 和 `weight` 只顯示在分鏡稿上，不決定成品的畫面：動畫只照 `scenes` 出現（見下面「scenes：動畫」）。現在選好，之後的期別才能直接用。

## 字幕用辨識文字的句子：找可能的錯字

`display_source` 是 `"asr"` 的句子，講的和腳本差太多（`ratio` 低於 0.50），字幕用的是辨識出來的字，所以可能有錯字。關卡 1 要你在註記和訊息裡指出來，使用者回「可以」，錯字就留在成品裡（訊息怎麼寫見 `reel` skill）。你看得到文字、聽不到聲音，所以只說「可能」。

把 `text`（字幕上的字）和 `script_text`（腳本原文）對照著看：

- 兩邊同一個位置的字不一樣，但讀音相同或相近（例如「多成兩小時」對「多撐兩小時」）：最可能是辨識錯的字。
- 專有名詞、品牌、英文和數字：腳本的寫法才是使用者要的（例如腳本寫「CP值」，辨識成「西皮值」）。
- 辨識的字讀起來不通順，或湊不成意思，就算腳本裡找不到對應的字，也可能是錯字。
- 只是講者換了說法（腳本「一天可以多撐兩小時」，辨識「大概多兩小時」）不是錯字，不用逐字挑。

訊息裡每一項只列看出來的幾個字：辨識的字是什麼，腳本對應的是什麼。沒看出錯字就直說。看出的錯字和改法也寫進這一句的註記（見下面「notes」），但不先改字幕的字：你聽不到聲音，由使用者決定。使用者要改的做法：直接改字幕的字（見下面「captions.text」）、改腳本重跑、拿掉這一句、重錄，或接受辨識出來的字，見 `reel` skill 的「字幕有錯字」。

## notes：要使用者決定的，各寫一句建議

`notes` 是代號對到一句註記：你給使用者的建議和理由。代號是 `trim.json` 的候選，或講者有講的句子。註記顯示在審閱頁的小卡上，也顯示在網頁（`review/gate1/index.html`）和 `storyboard.md` 的清單裡，使用者看得到：用中文寫，不寫代號，也不寫英文的原因。

一定要寫的有兩種：

- 每一個要使用者決定的候選：改詞重講（`kind` 是 `retake`、`suggest` 是 `list`），和 `length` 3 以上的腳本外的話（`kind` 是 `extra`）。
- 每一句字幕用辨識文字的句子（`display_source` 是 `"asr"`，講者有講，沒被 `cuts.extra` 移除）。

`validate` 不檢查這些有沒有寫（使用者在頁面上一切換，要決定的項目可能變多，強制會讓切換失敗），所以要自己記得寫。其他的（停頓、贅字、重複、NG、其他要聽的地方）不用寫：頁面依種類產生說明。

寫法一律是「建議…。因為…」：以「建議」開頭，說你建議怎麼做，接著「。因為」，說一句理由。`validate` 照這個檢查，不符合就報 `notes.<代號>: must start with 建議 and contain 。因為`。

- 候選的註記以「建議剪掉」或「建議保留」開頭：審閱頁照這四個字，把小卡上那個按鈕標成「（建議）」。建議要和 `cuts` 一致：建議剪掉的在 `cuts.accept`，建議保留的在 `cuts.reject`。改詞重講和腳本外的話怎麼判斷，見上面「cuts」。
- 字幕用辨識文字的句子：看出錯字，就寫具體的改法；沒看出，就建議他聽一下，理由說字幕是辨識出來的字。
- 理由和關卡 1 訊息裡的理由一致。
- 使用者改了決定（在頁面上或在對話裡），註記不用跟著改：它是你的建議，頁面照樣標出建議的那個，使用者選的另外顯示。

例子（句子是編的）：

```json
"notes": {
  "t05": "建議剪掉。因為這只是下一句講到一半的舊版本，沒有多講什麼。",
  "t08": "建議保留。因為「對了這個我昨天試過」是順口補的，聽起來自然。",
  "s07": "建議把「多成」改成「多撐」。因為讀音相同，應該是辨識錯的字。",
  "s11": "建議聽一下這一句。因為字幕是辨識出來的字，我看不出錯字，但可能有聽錯的地方。"
}
```

## captions

`captions` 是 `{"mode": "line"}` 或 `{"mode": "word"}`，可以再加 `text`（改字幕的字，見下面「captions.text」）。

- 預設 `line`：每一行是一個字幕事件，依序出現，不是整句一次顯示。一行最多 16 個字寬（全形字算 1，半形字算 0.5）。斷行只在詞和詞之間或標點後面，斷詞靠 `pipeline setup` 下載的斷詞字典，加上 repo 裡的專案詞表 `pipeline/caption_words.txt`（補字典沒有的台灣用語和自媒體用語）。字典和詞表都不認得的詞（例如新造的詞）仍可能被拆到兩行。使用者指出這種詞時，補救是把它加進 `pipeline/caption_words.txt`，不是改 `edit.json`：這是 repo 裡的檔案，先告訴使用者要加哪個詞，經他同意再改。詞表是所有專案共用的，改了之後，用到它的分鏡稿都要重做：重跑 `storyboard`，講給使用者聽，取得新的同意。一個子句一行：除了頓號「、」，每個標點後面都換下一行，不管那個子句多短，兩個子句不會擠在同一行；逗號、句號這些標點本身不顯示，問號、驚嘆號和引號、括號照樣顯示。頓號在行中照原樣顯示，在行尾拿掉。一個子句超過一行寬時，在子句裡照這個順序挑最好的斷法：行數最少；短行（兩個字寬以下）最少；不在頓號後面斷開的次數最少；第二行起以助詞（的、地、得、了、著、們，和句尾的嗎、呢、吧、啊、呀、啦、喔、哦、嘛、耶、囉）開頭的行最少，看的是行首的第一個字；各行長度最平均。講到那一行的第一個字時它出現；下一行出現時它就消失，下一行還沒出現的話，最晚在它的最後一個字說完 0.5 秒後消失。例如（句子是編的）「好，先把螢幕亮度調低，再關掉背景更新、定位、藍牙，這樣電池就可以比原本多撐好幾個小時。」會依序出現五行：「好」、「先把螢幕亮度調低」、「再關掉背景更新、定位、藍牙」、「這樣電池就可以比」、「原本多撐好幾個小時」。最後一個子句有 18 個字，放不進一行，所以在詞和詞之間分成兩行。
- 一串英文字母和數字算一個詞。有一個詞比一行還寬（例如很長的網址）時，只有那個詞從中間斷開，斷在字元之間；分鏡稿那一句會標「有詞太長，從中間斷開」，警告也會列出來（見 `reel` skill）。
- 只有使用者要逐字高亮時才用 `word`。斷行和 `line` 一樣，也是一行一個字幕事件。

### captions.text：改字幕的字

`captions.text` 是句子代號對到那一句字幕要顯示的字。例子（句子是編的）：

```json
"captions": {"mode": "line", "text": {"s12": "大概多撐兩小時吧"}}
```

- 什麼時候寫：使用者要改某一句字幕的字，例如在對話裡說「1:48 那句字幕改成…」，或同意你在註記裡建議的改法。字幕取自腳本或辨識出來的句子都能改。這是改錯字最直接的做法，不用改腳本、從 `transcribe` 重跑；那個做法照舊可以用（見 `reel` skill「字幕有錯字」）。審閱頁上的「改字幕」也是寫這個鍵。
- 不要自己先寫：字幕用辨識文字的句子，你看出的錯字寫在註記裡，由使用者決定。有 `captions.text` 的句子不再列在「要你決定」或「其他要聽的地方」，使用者就不會被問到這一句。
- 寫整句要顯示的字，不是只寫改的那幾個字。只能一行，不能有換行；去掉空白之後不能是空的；至少要有一個會顯示的字，只有標點或記號不行。
- 代號必須是講者有講的句子。這一句被 `cuts.extra` 移除時，改過的字留著不用，復原之後照舊顯示。
- 字幕出現的時間：改過的字和原本的字（`transcript.json` 裡這一句的 `text`）逐字對照。沒改的字，時間不變；換掉的字，用原本那幾個字的時間；新加的字，用它前一個字的時間（在句首的，用後一個字的）。
- 空白和標點照上面字幕顯示的規則處理，不佔自己的時間。Markdown 記號（成對的 `**` 這類強調記號、反引號，連結 `[文字](網址)` 的括號和網址）不顯示，和腳本裡的一樣。
- 斷行照上面 `line` 的規則，用改過的字斷。
- 字幕字型畫不出來的字（例如 emoji）不要寫。審閱頁存之前會擋下，說是哪個字；`validate` 和 `storyboard` 不擋，到 `render` 才拒絕（`the caption font … has no glyph for: …`，後面列出那些字），那時要改 `edit.json`、重做分鏡稿、重新取得同意。使用者要這種字，告訴他字幕的字型畫不出來。

## punch_in：推近

推近是在剪接點（剪掉一段、接到下一段的地方）把畫面放大一點。不寫 `punch_in` 時，整支都是原尺寸（9:16 的畫面），剪接點直接接起來。只在使用者要的地方推近，不要自己加。

- 放大時以講者的臉為中心：臉留在畫面上原來的位置，畫面只是往外推。字幕的位置不變。
- 景別只在剪接點換：一個片段（兩個剪接點之間的一段）從頭到尾是同一個景別。
- 放大的片段後面接著一個短於 1 秒的片段時，短的那段也放大，畫面才不會閃一下。

`punch_in` 是句子代號對到倍數（1 到 1.2 的數字，1 就是原尺寸）：從這一句開始的每個片段都放大這個倍數，其他片段不受影響。使用者沒說倍數就寫 1.1；要放大多一點寫 1.2（上限）。例子（句子是編的）：

| 句子 | 內容 | 使用者說 | 寫成 |
|---|---|---|---|
| `s03` | 其實把亮度調低，一天可以多撐兩小時。 | 「0:12 那句放大」 | 1.1 |
| `s07` | 背景更新也很耗電。 | 「0:31 那裡放大多一點」 | 1.2 |

```json
"punch_in": {"s03": 1.1, "s07": 1.2}
```

分鏡稿句子表的「推近」欄，列出從這一句開始、有放大的每個片段：它在成品裡從幾秒到幾秒、放大幾倍（「0:11.6 到 0:15.0 放大 1.1 倍」）；沒有的話這一欄空白。摘要的「推近」是剪接點幾個、放大幾段。審閱頁播放時照樣放大，但不能在頁面上改。

- 從使用者說的時間找句子：先找那個時間在講的句子（句子表裡「新時間」不晚於那個時間、而且最晚的那一句），寫進 `punch_in`，跑 `validate` 和 `storyboard`，看那一句的「推近」欄有沒有一段包含使用者說的時間。沒有（這一欄空白、`validate` 回了下面的警告，或列出的那段在那個時間之後才開始），表示那個時間播的片段是從更前面的句子開始的：把這一筆移到前一個保留的句子，再跑一次，直到包含為止。審閱頁上的時間也是成品裡的時間，找法一樣。
- 放大的是整個片段，所以可能比使用者說的那一句早開始或晚結束；一句裡開始好幾個片段時，全部都會放大，只放大其中一個做不到。告訴使用者實際放大的時間（「推近」欄列的那段）。
- 使用者說不要放大了：從 `punch_in` 拿掉那一筆。都拿掉了，就拿掉整個 `punch_in`。
- `validate` 擋下的：`punch_in.<代號>: must be a number from 1 to 1.2, got …`（倍數不是 1 到 1.2 的數字）；`not a spoken sentence`（句子沒講到，或腳本沒有這一句）。
- `validate` 通過、但 `warnings` 有 `punch_in.<代號>: no shot starts in this sentence, so it changes nothing`：沒有片段從這一句開始（這一句被整段移除，或剪接改了之後，片段改從別的句子開始），這一筆不起作用。審閱頁上切換剪掉或保留、拿掉一句，都可能造成這種情形：頁面不改 `punch_in`，也不因此擋下改動。看到這個警告，照上面重新找片段開始的那一句，把這一筆移過去，或拿掉，再 `validate`。句子是使用者在頁面上拿掉的，這一筆也可以留著：復原之後照舊起作用。
- 跟使用者說的時候，講景別（「原尺寸」「放大 1.2 倍」）和句子的內容、時間，不講代號。改完照常 `validate`、`storyboard`，再取得同意。

## scenes：動畫

動畫是疊在口播畫面上的卡片：講到某個字時出現，講到某個字或某一句講完時消失。卡片畫在畫面上方的動畫區，不擋到字幕，字幕照樣在最上層。不寫 `scenes` 時，成品沒有動畫。動畫只在使用者要的地方加，不要自己加，和推近一樣：使用者說「0:12 那句放數字卡」「開頭打出省電小技巧」這類話時才寫。

本期有三張卡：

| `card` | 名稱 | `params` | 樣子 |
|---|---|---|---|
| `keyword-pop` | 重點字 | `text`：1 到 10 個字寬 | 強調色的圓角塊，裡面一行粗體字，彈出來 |
| `number-slab` | 數字卡 | `value`：1 到 6 個字寬；`label`：0 到 12 個字寬，可以省略 | 白色圓角卡，大字的數字，下面一行說明 |
| `bullet-list` | 清單 | `items`：2 到 4 項，每項 1 到 12 個字寬 | 白色圓角卡，一項一項出現，每項前面打一個勾 |

- 卡片上的字由你從那一句的內容摘出來，越短越好。告訴使用者卡片上寫什麼。
- 字寬照字幕的算法：全形字算 1，半形字算 0.5，前後的空白不算。每段文字只能一行。
- 英文字母和數字畫出來比半個中文字寬，所以字寬沒超過，卡片還是可能比動畫區寬。`validate` 用卡片的字型量，太寬就擋下：`scenes[0].params.text: 1076 px wide on its card, wider than the 950 px animation zone`。縮短那段文字，或改用中文。
- 卡片字型畫不出來的字（例如 emoji）不要寫。`validate` 和 `storyboard` 不擋，到 `render` 才拒絕（`the card font … has no glyph for: …`，後面列出那些字），那時要改 `edit.json`、重做分鏡稿、重新取得同意。
- 使用者要的動畫這三張做不到（圖表、箭頭、貼紙、整個畫面換成卡片、B-roll）：告訴他這個版本只有這三張卡。

`scenes` 是一個陣列，每一筆是一段動畫：

- `id`：不重複的字串，例如 `sc1`。
- `card`：上表的三張卡之一。`params`：那張卡的參數，照上表。
- `layout` 可以省略；寫了只能是 `"overlay"`（疊在口播畫面上）。
- `at`：出現的位置，`{"s": 句子代號, "char": n}`。`n` 是這一句字幕的字（`transcript.json` 裡這一句的 `text`）的第幾個字，從 0 起算，標點也算；省略 `char` 就是 0。動畫在這個字開始講的時候出現。改過字幕的句子（`captions.text`）也照 `text` 數，不照改過的字。
- `until`：消失的位置。`{"s": 句子代號, "end": true}` 是那一句講完，`{"s": 句子代號, "char": n}` 是第 n 個字講完。可以是後面的句子（一段動畫跨好幾句），不能在 `at` 之前。
- `at` 和 `until` 的句子都要是講者有講的句子。

例子（句子是編的）：

| 句子 | 內容 | 使用者說 | 寫成 |
|---|---|---|---|
| `s01` | 今天來聊三個省電的小技巧。 | 「開頭打出省電小技巧」 | 重點字，從 `char` 6（「省」）到這一句講完 |
| `s03` | 其實把亮度調低，一天可以多撐兩小時。 | 「0:12 那句放數字卡」 | 數字卡，從 `char` 8（「一」）到這一句講完 |
| `s08` | 第一是亮度，第二是背景更新，第三是定位。 | 「這句列成清單」 | 清單，整句 |

```json
"scenes": [
  {"id": "sc1", "card": "keyword-pop", "at": {"s": "s01", "char": 6}, "until": {"s": "s01", "end": true},
   "params": {"text": "省電小技巧"}},
  {"id": "sc2", "card": "number-slab", "at": {"s": "s03", "char": 8}, "until": {"s": "s03", "end": true},
   "params": {"value": "兩小時", "label": "一天多撐"}},
  {"id": "sc3", "card": "bullet-list", "at": {"s": "s08"}, "until": {"s": "s08", "end": true},
   "params": {"items": ["亮度", "背景更新", "定位"]}}
]
```

- 從使用者說的時間找句子：和推近一樣，先找那個時間在講的句子（句子表裡「新時間」不晚於那個時間、而且最晚的那一句），再從這一句的字挑 `char`。跑過 `validate` 和 `storyboard`，看那一句的「動畫」欄列的時間，告訴使用者動畫實際從幾秒到幾秒。
- `validate` 擋下的，除了格式和參數不合：兩段動畫的時間重疊（`scenes[1]: overlaps scenes[0]`；動畫區只有一個）；同一張卡照出現的順序連用 3 次（`scenes[2]: the third keyword-pop in a row`）。`scenes[n]` 是 `scenes` 的第幾筆，從 0 起算。
- `validate` 通過、但 `warnings` 有這三種，表示剪接讓動畫出不來或太短。審閱頁上切換剪掉或保留、拿掉一句，都可能造成這種情形：頁面不改 `scenes`，也不因此擋下改動。
  - `scenes[n]: <句子代號> is removed by cuts.extra, so it is not shown`：動畫用到的句子被整段移除了。句子是使用者在頁面上拿掉的，這一筆可以留著：復原之後照舊出現。
  - `scenes[n]: nothing of it is left after the cuts, so it is not shown`：動畫的時間全在剪掉的地方。
  - `scenes[n]: 0.6 s long after the cuts, under 1 s`：剪完只剩不到 1 秒，卡片一出現就消失。

  看到這些警告，用中文告訴使用者是哪一段動畫（卡片的名稱、上面的字），問他要移到哪裡或拿掉，再 `validate`。
- 分鏡稿句子表的「動畫」欄，在動畫出現的那一句（`at` 的句子），寫卡片的名稱、文字和成品裡的時間（「數字卡：兩小時／一天多撐（0:12.0 到 0:14.5）」）；摘要的「動畫」是會出現的段數。上面的警告在分鏡稿的警告裡是中文。
- 審閱頁播到動畫的時段，在影片上方標出卡片的名稱和文字（「動畫：數字卡　兩小時／一天多撐」），不播真的動畫，也不能在頁面上改。真的動畫要輸出成品才看得到。
- 使用者說不要這段動畫了：從 `scenes` 拿掉那一筆。都拿掉了，就拿掉整個 `scenes`。跟使用者說的時候，講卡片的名稱、上面的字和句子的時間，不講代號。改完照常 `validate`、`storyboard`，再取得同意。

## 寫完一定跑 validate

寫完或改完 `edit.json`，馬上跑 `uv run pipeline validate <專案>`。

- 通過：結果有 `segments`（保留的片段數）、`duration_s`（剪完的長度）和 `kept_sentences`（保留的句子數）。
- 不通過：結束碼 2，`errors` 列出每一個問題，格式是「位置：問題」，例如 `cuts: trim t03 is neither accepted nor rejected`。照著改，再跑一次，直到通過。
- 不要因為「看起來沒問題」就跳過。之後的 `storyboard` 和 `render` 也會檢查，但在這裡就擋下來，才不會用一份壞檔案去講給使用者聽。

通過的 `validate` 會讓 `pipeline` 記下它檢查的是哪個 `edit.json`、`transcript.json` 和 `trim.json`。這三個檔案只要有一個和紀錄不同，`storyboard` 就拒絕，`status` 的 `next` 也會回到 `validate` 或 `edit`：

- `edit.json` 改過，就要再跑 `validate`。
- `transcribe` 或 `trim` 重跑過，候選代號（`t01`、`t02`…）和句子代號（`s01`、`s02`…）都可能指向不同的內容，舊的 `edit.json` 卻可能照樣通過 `validate`。這時要逐一重新核對：`cuts.accept` 和 `cuts.reject` 的每一個候選，從新的 `trim.json` 重新決定，不沿用舊的決定；`cuts.extra`、`sentences`、`captions.text`、`punch_in` 的每一個句子代號，對照新的 `transcript.json`；`notes` 的代號也一樣，候選的照新的 `trim.json`，句子的照新的 `transcript.json`。核對完再跑 `validate`。做法，以及 `edit.json` 內容沒變時 `validate` 回的 `warnings` 怎麼處理，見 `reel` skill 第 6 節。

分鏡稿用到的檔案（`edit.json`、`transcript.json`、`trim.json` 等）只要有一個改過，就要重跑 `storyboard`，並取得使用者新的同意（見 `reel` skill）。
