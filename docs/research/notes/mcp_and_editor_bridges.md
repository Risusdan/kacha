# MCP servers and editor bridges for Claude Code / Claude Desktop video work (state as of 2026-11-11)

Method note for the report writer: repository numbers (stars, forks, last push, created, license, archived flag) were pulled from the GitHub REST search API on 2026-11-11 for every repo named below. "Last push" is GitHub's `pushed_at` field (the last push to any branch), which is a close proxy for, but not identical to, the last commit date. Feature descriptions come from each repo's README as fetched on 2026-11-11 unless marked as coming from a directory listing or a search snippet. Directory sites (Glama, LobeHub, mcpservers.org, PyPI listings) were often stale or inconsistent with the READMEs; where they disagree, the README wins and the conflict is noted.

## 1. ffmpeg MCP servers: what they expose, and do they beat Claude Code running ffmpeg through Bash?

### Takeaway
The ffmpeg MCP servers are thin wrappers that turn single ffmpeg operations (trim, convert, overlay text, concat) into MCP tools. Most are small, and several have had no pushes since 2025. For Claude Code, which already has a shell, they add tool-schema tokens and one more dependency without adding capability. They are worth it mainly for Claude Desktop (no shell) or when you want a fixed, permissioned tool surface instead of arbitrary shell commands.

- Where MCP overhead comes from: tool schema definitions are loaded into the context window, while a CLI agent uses commands the model already knows. Reported measurements vary widely: one author reports ~9,542 tokens for a base MCP schema versus 344 for a CLI schema; another ~1,300 tokens for 21 MCP tool schemas at session start; a Firecrawl comparison ~44K tokens with full schema loaded versus ~200 per CLI command. — search-result summaries of [Firecrawl: MCP vs CLI](https://www.firecrawl.dev/blog/mcp-vs-cli), [dev.to: CLI vs MCP](https://dev.to/pickuma/cli-vs-mcp-which-tool-interface-actually-works-for-ai-coding-agents-1894) (pages not fetched; figures are blog measurements, not controlled studies)
- One writeup reports 100% task success for CLI versus 72% for MCP and estimates about $3.20 versus $55.20 per 10,000 operations — [Kaxil Naik, "MCP Sucks (Until It Doesn't)"](https://kaxil.substack.com/p/mcp-vs-cli-vs-rest) (via search snippet, not fetched). Counter-example: a hands-on test found MCP used fewer tokens for fetching a web page (250 vs 2,000+) — [Towards AI](https://pub.towardsai.net/cli-vs-mcp-i-ran-the-same-task-through-both-one-used-250-tokens-the-other-used-over-2-000-c4c460202d52) (via search snippet).
- The most-starred agent video editor of 2026, browser-use/video-use (30,861 stars, see section 6), is a skill that drives ffmpeg directly; it is not an MCP server. — [video-use README](https://github.com/browser-use/video-use)

### Inferences
- For a Claude Code pipeline, the ffmpeg MCPs above do not beat Bash plus ffmpeg: each tool is one ffmpeg invocation with fewer knobs than the CLI, they cost schema tokens every session, and most are single-day or stale projects. A small set of project scripts (for example `make_contact_sheet.sh`, `burn_subtitles.py`) called from Claude Code, or a skill that documents them, gives the same safety benefit (fixed, reviewed commands) with no server to maintain.
- An ffmpeg MCP is defensible only for Claude Desktop users who have no shell, or as a way to restrict the agent to an allowlist of operations. Even then, `ffmpeg_raw`-style tools (PedroMarianoAlmeida) remove that restriction.
- HYPOTHESIS: Claude Code's deferred MCP tool loading (tool schemas fetched on demand rather than all at session start) narrows the token-overhead gap reported in the 2025 blog posts. This was observed in this research session's own harness, not checked against Claude Code documentation; confirm in the Claude Code MCP docs before relying on it.

### Gaps
- No controlled benchmark of "ffmpeg MCP vs ffmpeg via Bash" for video tasks was found; all overhead figures are generic MCP-vs-CLI blog measurements.
- `KyaniteLabs/mcp-video`, `ZizoTheDev/ffmpeg-mcp` and `conneroisu/vfx-mcp` (named in directories) were not returned by the GitHub search API on 2026-11-11; they may be renamed, private, or not indexed.

## 2. NLE bridges: DaVinci Resolve, Premiere Pro, After Effects, Final Cut Pro, CapCut / Jianying (剪映)

### Takeaway
DaVinci Resolve is the most mature target (samuelgursky/davinci-resolve-mcp, 4,035 stars, pushed 2026-11-10, plus a native Studio-only MCP server in Resolve 21.1), but Resolve 21.1 moved Python and external scripting to the paid Studio edition, so a free-Resolve pipeline is fragile. Premiere has one serious community bridge (hetpatel-11, CEP-based, macOS-validated). Final Cut Pro works through FCPXML files and is macOS-only. For CapCut/Jianying, draft generators (pyJianYingDraft, VectCutAPI, capcut-mate) do produce editable drafts the creator can open and fine-tune, but they reverse-engineer an undocumented, partly encrypted format and break when the app updates.

### Inferences
- Adopt-vs-script for Resolve: samuelgursky's server is the only NLE bridge with clear momentum (4k stars, daily pushes, broad API coverage, Claude Code installer). But the creator would need Resolve Studio for a reliable external-scripting path after 21.1, and once on Studio, Resolve's own native MCP server is an alternative. If the creator stays on free Resolve, generating a timeline file (OTIO/FCPXML/EDL, section 3) from Claude Code scripts is the sturdier route.
- Premiere: hetpatel-11 is the only bridge with real adoption; Windows is essentially untested by the maintainer. The other Premiere bridges are prototypes (5 stars, single-day repos).
- After Effects bridges are relevant only if the creator already uses AE for motion graphics; Dakkshin's repo has had no push since 2026-04-01.
- Final Cut: FCPXML MCPs are workable and active, but the whole path is macOS-only (live mode explicitly so, and Final Cut itself is an Apple Mac app), so it would not carry over to a later Windows version.
- CapCut/剪映: yes, the generators can produce an editable draft the creator opens and fine-tunes, which fits a "Claude does the rough cut, human polishes in CapCut" workflow. The risk is format churn: encryption since 剪映 6, hidden export controls since 剪映 7, and reports of CapCut 8.7+ ignoring or rejecting tool-written drafts. Expect breakage after app auto-updates; pin the app version if possible and test on a copy. Jianying (China) is better supported than CapCut international (pyCapCut is still "in development"; VectCutAPI has a `capcut_legacy` profile only). Since VectCutAPI and capcut-mate both build on pyJianYingDraft-style reverse engineering, adopting VectCutAPI's MCP mode buys convenience but not robustness over calling pyJianYingDraft/pyCapCut directly from a Claude Code script.
- Export (rendering the final MP4) from 剪映 drafts by automation is effectively Windows-only and limited to old versions; on a Mac the creator would render manually inside the app.

### Gaps
- Which exact CapCut international desktop versions (macOS and Windows) accept drafts from VectCutAPI/pyCapCut as of November 2026 could not be confirmed; no maintainer compatibility matrix for CapCut international was found.
- Whether Resolve free 21.1 still runs the samuelgursky in-app bridge (Python vs Lua) is unconfirmed by its own README; Digital Production and Puget disagree on whether any scripting remains in free 21.1.
- The scope of Adobe's hosted "Adobe for creativity" connector for Premiere timelines could not be verified from Adobe documentation.
- After Effects bridges' Windows support and current maintenance were not verified from their READMEs.

## 3. Interchange formats: EDL, FCPXML, OpenTimelineIO (OTIO)

### Takeaway
A Claude Code pipeline can write a timeline file that DaVinci Resolve (OTIO since 18.5) and Final Cut Pro (FCPXML) import natively; Premiere's OTIO support was still beta-only as of the latest Adobe statement found. CapCut/剪映 has no documented timeline import, so the only way to hand the creator an editable CapCut project is the draft-generator route in section 2. Interchange carries cuts, tracks, speed and markers, not effects, titles or transitions.

### Cited Findings
- [AcademySoftwareFoundation/OpenTimelineIO](https://github.com/AcademySoftwareFoundation/OpenTimelineIO): 2,068 stars, 361 forks, last push 2026-11-07, Apache-2.0, "Open Source API and interchange format for editorial timeline information" (GitHub API, 2026-11-11).
- DaVinci Resolve supports OTIO import and export; the Resolve 18.6 manual states it supports "the Open Timeline IO (OTIO) format for importing and exporting timelines between applications"; one source dates this to Resolve 18.5; the OTIO apps directory lists Resolve with OTIO and OTIOZ import/export. — [Resolve 18.6 manual mirror](https://www.steakunderwater.com/VFXPedia/__man/Resolve18-6/DaVinciResolve18_Manual_files/part1411.htm), [OTIO apps and tools](https://otio-website.vercel.app/apps-and-tools)
- Premiere Pro: Adobe's post "[Now Released] OTIO Import and Export" (2024-10-23) refers to Premiere Pro Beta. On 2025-02-12 Adobe's Bruce Bullis wrote "OTIO support will move from PPro beta to official releases, when the functionality and quality are up to a release standard. We're not there yet." Supported: clip names and cut list, source in/out, durations, timecode, frame rate, multiple tracks and names, linear speed, sequence markers; round-trip-only data for clip markers, frame size and sample rate. Effects, transitions and titles are not mentioned; After Effects has no plans for OTIO. A March 2026 user report says clip names revert to file names after a Premiere to OTIO to Premiere round trip. — [Adobe community announcement](https://community.adobe.com/announcements-732/now-released-otio-import-and-export-311699)
- A December 2025 thread reports a Windows path problem moving OTIO between Premiere Beta 26.1 and Resolve 20.2. — search-result summary of [Adobe beta forum](https://community.adobe.com/t5/premiere-pro-beta-discussions/now-in-beta-otio-import-and-export/m-p/15486928)
- Known OTIO cross-app issue: track ordering inverts when moving a Kdenlive OTIO into Resolve, and missing-asset prompts fail across machines. — [KDE bug 503692](https://bugs.kde.org/show_bug.cgi?id=503692)
- FCPXML: Final Cut Pro has a fully scriptable import and no programmatic export; DareDev256's server reads, edits and generates FCPXML and can push it into a running Final Cut (macOS only). — [Glama: fcp-mcp-server](https://glama.ai/mcp/servers/DareDev256/fcp-mcp-server); [GitHub](https://github.com/DareDev256/fcp-mcp-server)
- samuelgursky/davinci-resolve-mcp lists "timeline editing and conform" among its tool categories, i.e. it can conform imported timelines inside Resolve. — [README](https://github.com/samuelgursky/davinci-resolve-mcp)

### Inferences
- Best cross-NLE handoff for this project: have Claude Code scripts emit OTIO (via the `opentimelineio` Python library) for Resolve, and FCPXML for Final Cut; treat Premiere OTIO as beta. Keep effects, captions styling and motion graphics as either burned-in renders or separate overlay media placed on their own track, because interchange formats drop them.
- For a creator who finishes in CapCut, a timeline interchange file is not an option; the choice is between (a) generating a CapCut/剪映 draft (fragile, editable) and (b) rendering a finished MP4 with ffmpeg and doing light touch-ups in CapCut on the rendered file (robust, but cuts are baked in).

### Gaps
- Not verified in this session: which OTIO adapters (FCPXML, CMX 3600 EDL, AAF) currently ship with the OTIO Python package versus as separate plugin packages; check the OTIO docs before choosing an export path.
- Not verified: whether Premiere's OTIO import moved out of beta in any 2026 release; the latest Adobe statement found (Feb 2025) says it had not.
- EDL (CMX 3600) import support in Resolve/Premiere was not re-checked against current vendor docs in this research.
- No evidence found of CapCut or 剪映 importing OTIO, FCPXML or EDL.

## 4. Video understanding for QA: how the agent "sees" its own output, and what it costs

### Takeaway
Three patterns exist: (1) extract frames or a contact sheet with ffmpeg and have Claude read the PNG (cheap, local, no extra vendor; Claude sees stills, not motion or audio); (2) send the whole video to Gemini through an MCP or script (sees motion and audio at about 100 tokens per second of video, but requires a Google API key and upload); (3) Twelve Labs' hosted MCP (indexing/search/Q&A over uploaded video, OAuth, text-only answers in Claude Code). The most-adopted agent editor (video-use) avoids watching video at all: it reads a word-level transcript and looks at a composite filmstrip PNG only at decision points and cut boundaries.

### Cited Findings
- Claude image cost: "An image ... costs `⌈width / 28⌉ × ⌈height / 28⌉` visual tokens." High-resolution tier (Claude 4.7 and later models): long-edge limit 2,576 px, cap 4,784 tokens; standard tier (all other models): 1,568 px, 1,568 tokens. A 1920x1080 image costs 1,560 tokens on the standard tier (downsized to 1456x819) and 2,691 tokens on the high-resolution tier (not resized). At Claude Opus 5.5's $4 per million input tokens, a 1000x1000 image costs about $5.18 per thousand. — [Claude vision docs](https://platform.claude.com/docs/en/build-with-claude/vision)
- Same doc: if a request contains more than 20 images, a stricter per-image dimension limit applies to every image, and images from earlier turns that are resent (including images inside `tool_result`) count toward the 20; keeping each dimension at or below 3,000 px avoids rejection. — [Claude vision docs](https://platform.claude.com/docs/en/build-with-claude/vision)
- Gemini video: "Approximately 100 tokens per second of video at default (low) media resolution", "approximately 300 tokens per second" at high resolution; frames extracted at 1 FPS by default, configurable via an `fps` value in the `processing` config (example `0.5`); 1M-context models handle up to 3 hours at low resolution or 1 hour at high; File API limit 20 GB paid / 2 GB free; the page gives inline limits of both "< 100MB" and "under 20MB" without reconciling them. No last-updated date shown. — [Gemini API video understanding](https://aistudio.google.com/docs/video-understanding)
- Gemini MCPs for Claude Code: `ugarchance/mcp-gemini-video-understanding` (npm; local files and YouTube URLs; needs `GEMINI_API_KEY`) has 0 stars and last push 2025-10-11 (GitHub API, 2026-11-11; [LobeHub](https://lobehub.com/mcp/ugarchance-mcp-gemini-video-understanding)). `video-research-mcp` installs with `claude mcp add -e "GEMINI_API_KEY=${GEMINI_API_KEY}" video-research-mcp -- uvx video-research-mcp` and is described as a plugin with 45 tools, 17 slash commands, 7 skills and 7 sub-agents — [conare.ai listing](https://conare.ai/marketplace/mcp/video-research-mcp) (repository owner and maturity not verified).
- Twelve Labs: official hosted MCP. The cross-video "Jockey" server is at `https://mcp.twelvelabs.io/jockey/mcp` (remote HTTP, OAuth) and manages knowledge stores, adds media from URLs, checks indexing status, searches and answers questions. Claude Code install: `claude mcp add --transport http --scope user jockey https://mcp.twelvelabs.io/jockey/mcp`, then authenticate via `/mcp`. Widgets (galleries, timelines, highlight reels) render in Claude; "Claude Code receives written answers instead". Single-video tools (search, analysis, embeddings) moved to `mcp-alpic.twelvelabs.io`. No pricing on the page; a free account is available. — [Twelve Labs MCP docs](https://docs.twelvelabs.io/docs/advanced/model-context-protocol); launch post: [Twelve Labs blog](https://www.twelvelabs.io/blog/twelve-labs-mcp-server)
- video-use: "The LLM never watches the video. It **reads** it." Always-loaded layer: ElevenLabs Scribe transcript with word-level timestamps, speaker diarization and audio events packed into ~12 KB `takes_packed.md`. On-demand layer: `timeline_view` renders a PNG with filmstrip, waveform and word labels. It "Self-evaluates the rendered output at every cut boundary before showing you anything", fixing and re-rendering up to three times. Author's cost contrast: "30,000 frames × 1,500 tokens = 45M tokens" for frame dumping versus "12KB text + a handful of PNGs". Requires ffmpeg and an ElevenLabs API key. — [video-use README](https://github.com/browser-use/video-use)
- HyperFrames ships lint and frame-inspection steps in its CLI and a browser preview (`npx hyperframes preview`); the README does not describe agent self-review beyond that. — [HyperFrames README](https://github.com/heygen-com/hyperframes)
- samuelgursky/davinci-resolve-mcp lists "media analysis" and "review annotations" categories; optional analysis needs ffmpeg, Whisper or librosa, not bundled. — [README](https://github.com/samuelgursky/davinci-resolve-mcp)

### Inferences
Computed from the Claude formula above (not measured in a real run):
- One full 1080x1920 vertical frame on a high-resolution-tier model: ⌈1080/28⌉ × ⌈1920/28⌉ = 39 × 69 = 2,691 tokens, about $0.011 at $4 per million input tokens. On a standard-tier model it is downsized to the 1,568 px long edge and costs about 1,560 tokens.
- A contact sheet that tiles 9 frames at 360x640 (3x3) or 16 frames at 270x480 (4x4) into one 1080x1920 image costs the same 2,691 tokens, i.e. about 300 or 170 tokens per frame. This is the cheapest way to check framing, safe zones, subtitle placement and colour across a whole reel; fine text legibility needs a full-resolution single frame.
- Reviewing a 60-second reel at 1 frame per second as full-resolution frames: 60 × 2,691 ≈ 161,000 tokens (about $0.65 at $4 per million) and it trips the >20-images-per-request rule unless frames are downsized or batched. A 60-second reel in Gemini at the default resolution is about 6,000 tokens by Google's stated rate, and it covers motion and audio, which stills do not.
- Practical QA stack for this project: ffmpeg contact sheets plus a few full-res frames at cut points (read by Claude Code), a transcript/subtitle diff for audio-text sync, and `ffprobe`/loudness checks as plain scripts; add a Gemini pass only for motion- or audio-dependent questions (pacing, beat sync, jump-cut smoothness). Twelve Labs is aimed at searching libraries of footage, which is more than a single-reel QA loop needs, and it requires uploading media to its cloud.

### Gaps
- Gemini per-token price for video input was not retrieved, so a dollar comparison with Claude frames is incomplete.
- Twelve Labs indexing/analysis pricing per minute was not found on the MCP docs page.
- Whether Claude Code's Read tool resizes images before sending them (which would change the token math) was not checked.
- No independent measurement of video-use's token claims was found.

## 5. Asset and media MCPs (stock footage and music, image generation, Lottie, icons) and commercial licensing on Instagram

### Takeaway
LottieFiles runs an official hosted MCP (OAuth, workspace and animation management through GraphQL tools). Stock media (Pexels, Pixabay, Unsplash) and image generation (fal, Replicate, OpenAI) are reachable only through community MCP servers; no vendor-owned image-generation MCP was found. These are thin API wrappers, so a script with the vendor's REST API is an equal alternative in Claude Code. Licensing: Pexels and Pixabay allow commercial use without attribution, with trademark and people caveats; music on business or branded Instagram accounts is restricted to Meta's commercial audio library or licensed tracks.

### Cited Findings
- LottieFiles official MCP: endpoint `https://mcp.lottiefiles.com/mcp`, no install or API key, browser OAuth sign-in; four GraphQL workbench tools (`operations_list`, `schema_search`, `schema_details`, `graphql_execute`) to "search, organize, and update your workspaces, projects, and animations"; animation creation is handled by a separate "Creator MCP", and in-editor building by "Lottie Creator WebMCP". No paid-plan or commercial-licensing information on the page. Page "Last updated: November 10, 2026". — [LottieFiles MCP docs](https://docs.lottiefiles.com/en/platform/mcp)
- Community `mcp-server-lottiefiles` (npm, by junmer, MIT) searches and retrieves animations; some directories mislabel it as maintained by LottieFiles. — [npm](https://npmjs.com/package/mcp-server-lottiefiles); [Glama](https://glama.ai/mcp/servers/junmer/mcp-server-lottiefiles)
- Stock media MCPs (community): `stock-images-mcp` searches and downloads from Pexels, Unsplash and Pixabay with API keys in environment variables (tools `search_images`, `download_image`); a Pexels server handles stock footage with clip previews and author/licence metadata for credits; a Pixabay server covers images and videos. — [LobeHub: jeanpfs/stock-images-mcp](https://lobehub.com/mcp/jeanpfs-stock-images-mcp), [Glama: Pexels integrations](https://glama.ai/mcp/servers/integrations/pexels), [Glama: Pixabay MCP](https://glama.ai/mcp/servers/@Unlock-MCP/pixabay-mcp-server/tree/11b5ee2e8a1d9f81f3deaefe3528599225a368e5) (directory listings, not verified against repos)
- Image generation MCPs found were all community projects (multi-provider via OpenRouter/Together/Replicate/fal; `iplanwebsites/image-mcp` wrapping OpenAI and Replicate; `Gravicity/fal-mcp-server`; `aicoder2048/img_gen_replicate_mcp`); the search surfaced no vendor-owned server from fal, Replicate or OpenAI. — [mcpservers.org: image-mcp](https://mcpservers.org/servers/iplanwebsites/image-mcp), [Glama: Gravicity fal-mcp-server](https://glama.ai/mcp/servers/@Gravicity/fal-mcp-server/blob/187bfbe2841238835d96ee3beb2bbcfcac123c00/README.md), [Glama: Replicate MCP](https://glama.ai/mcp/servers/aicoder2048/img_gen_replicate_mcp)
- Adobe's hosted connector reportedly includes Firefly and Adobe Stock tools (status disputed, see section 2). — [mcpservers.org](https://mcpservers.org/remote-mcp-servers/adobe-creativity)
- Pixabay License: content free for commercial and non-commercial use; "if Content contains any recognisable trademarks, logos or brands, you cannot use that Content for commercial purposes in relation to goods and services"; depicted content may still carry trademark, publicity or privacy rights. — [Pixabay Content License Summary](https://pixabay.com/en/service/license/) (via search summary)
- Pexels: use and modify for free, commercial and personal, without attribution — [University of Saskatchewan EdTech](https://sites.usask.ca/edtech/?p=2575) (secondary); some Pexels content is sponsored or partner-provided with extra restrictions — [licenseorg comparison](https://licenseorg.com/compare/pixabay-vs-pexels) (secondary). The Pexels license text itself was not retrieved.
- Instagram music: business accounts (brand accounts, accounts tagged in branded-content partnerships, accounts running ads) are restricted to a separate commercial audio library; for branded content use royalty-free tracks from the Facebook Sound Collection or a paid licence; crediting in a caption does not create a licence. — [ScreenApp guide, 2026](https://screenapp.io/blog/how-to-use-copyrighted-music-on-instagram-legally) (secondary vendor blog, not Meta's own terms)

### Inferences
- For Claude Code, asset fetching is a good fit for small scripts against the Pexels/Pixabay REST APIs (download plus a sidecar file recording source URL, author and licence), which also creates the credit/licence log a commercial account needs. The community MCPs add little beyond that.
- The LottieFiles official MCP is useful for finding and organising animations in the creator's LottieFiles workspace; rendering Lottie into a vertical video still needs a renderer (for example HyperFrames or Remotion in a headless browser), which is outside the MCP.
- If the account is a business or creator account doing paid partnerships, music should come from Meta's commercial library or a licensed library, not from stock-footage sites' audio unless their licence explicitly covers it.

### Gaps
- No icon-library MCP (e.g. Iconify, Lucide) was researched; not covered.
- Pixabay Music and Pexels audio licence terms for Instagram monetised or branded use were not checked against primary licence text.
- Meta's own current commercial-audio rules were not retrieved; only secondary blogs.
- Whether LottieFiles free-library animations are cleared for commercial social video was not on the MCP page; check the LottieFiles licence separately.
