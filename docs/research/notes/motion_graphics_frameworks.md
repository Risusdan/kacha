# Code-driven motion graphics frameworks that Claude Code can drive, for 1080x1920 short-form video (state as of 2026-11-11)

Research date: 2026-11-11. "Fetched" means the page was read directly on 2026-11-11. "Snippet" means the claim comes from a search-result summary and the page itself was not opened; treat those as weaker. Secondary/aggregator sources are labelled.

## Q1. Remotion: official agent skills / Claude Code integration, prompting, render requirements and speed, licensing

### Takeaway
Remotion (React, frame-number-driven, headless-Chromium render) is the most established option. Since early 2026 it ships official Agent Skills (now 13 slash-command skills) and a Claude Code plugin. A solo creator is covered by the free license. No one has published a render benchmark for a 60 s 1080x1920 clip, so render time has to be measured locally with `npx remotion benchmark`.

### Cited Findings
**Agent skills and plugin (official docs, fetched 2026-11-11)**
- Remotion's "Agent Skills" page describes the skills as best-practice instructions for AI agents (Claude Code, Codex, Kimi Code, Cursor) working in Remotion projects. Install with `npx skills add remotion-dev/skills`, `gh skill install remotion-dev/skills`, or `bun create video`, which offers to add the skills when it creates a project. No release date is shown on the page. — [Remotion docs: Agent Skills](https://www.remotion.dev/docs/ai/skills)
- The 13 skills listed are: `/remotion-best-practices` (the umbrella skill), `/remotion-create`, `/remotion-markup` (compositions, animations, layout, typography, media, effects, audio, fonts, timing), `/remotion-studio`, `/remotion-render`, `/remotion-maps`, `/remotion-captions`, `/remotion-saas`, `/remotion-interactivity`, `/remotion-docs` (searches the docs and fetches pages as Markdown), `/remotion-license` (from v4.0.540), `/remotion-upgrade` and `/remotion-multimedia` (Mediabunny). Skill source lives in `remotion-dev/remotion/packages/skills`. — [Remotion docs: Agent Skills](https://www.remotion.dev/docs/ai/skills)
- Claude Code plugin: `claude plugin marketplace add remotion-dev/claude-code-plugin`, then `claude plugin install remotion@remotion`, then restart Claude Code. The desktop app can also add it through Customize → Plugins → Discover. The docs give this usage example: `/remotion:remotion-create Make a promo video for a record store`. Sibling plugin pages exist for Codex, Cursor, Kimi Code and GitHub Copilot. — [Remotion docs: Claude Code plugin](https://remotion.dev/docs/ai/claude-code-plugin)
- Official quick start ("Prompting videos with coding agents"): run `npx create-video --yes --blank my-video`, then `npx remotion skills add`, then `npm run dev` for the Studio preview, and launch the agent in a separate terminal. The page has no prompting tips, no pitfalls and no rendering guidance, and it names Node.js without a version. — [Remotion docs: coding agents](https://www.remotion.dev/docs/ai/coding-agents)

**How practitioners prompt it**
- Example prompts from a 2026-01-25 walkthrough: "Create an app feature walkthrough video… each displayed for 3 seconds with fade transitions"; a 15-second TikTok-style vertical clip with spring fly-in and shake effects; a bar chart with counters that tick up as the bars rise. In a Chinese-language session the author asked Claude to combine a media-download skill with `remotion-best-practices` to build a "2025 Douyin Top 10" video. Claude scaffolded the data file, components, compositions and transitions, downloaded the audio and background clips, and started Studio. - Captioned talking-head pattern (cookbook updated June 2026): a captions overlay wrapped around `<OffthreadVideo src={staticFile('talk.mp4')}>`. The current frame is converted to milliseconds and matched against each caption's start and end times. — [mcp.directory Remotion skill guide](https://mcp.directory/blog/claude-remotion-skill-guide)
- Idle token cost of the skill is about 100 tokens (name and description only). The rule files load only when the skill triggers. — [mcp.directory](https://mcp.directory/blog/claude-remotion-skill-guide)

**Render requirements and speed**
- Node.js 18+. The first render downloads Chromium. Rendering is "slow and memory-intensive", 8 GB+ RAM is recommended, and test renders can use `--scale=0.5` and `--frame-range=0-100`. — [heyuan110.com, 2026-01-25](https://www.heyuan110.com/posts/ai/2026-01-26-claude-code-remotion-video/) (secondary; the official coding-agents page does not state a Node version)
- `npx remotion render` pulls a headless Chromium. `npx remotion still` can check layout before a full render. — [mcp.directory](https://mcp.directory/blog/claude-remotion-skill-guide)
- By default Remotion uses half of the available threads. Raising concurrency usually speeds up rendering, but setting it too high can make Chrome throttle. `npx remotion benchmark` compares concurrency values, and `--log=verbose` lists the slowest frames. — [Remotion docs: performance](https://www.remotion.dev/docs/performance); [Remotion docs: benchmark](https://remotion.dev/docs/cli/benchmark)
- No published benchmark exists for a 60 s 1080x1920 render (see Gaps). The only head-to-head timing found is HeyGen's single agent run, measured from prompt to rendered MP4 and including the agent's work: Remotion 12 min 30 s, HyperFrames 11 min 50 s. HeyGen itself says "a single run decides nothing about quality." The test used Claude Code (Opus 5.5). — [HyperFrames docs: HyperFrames vs Remotion](https://hyperframes.heygen.com/guides/hyperframes-vs-remotion) (vendor-authored)

**Licensing (fetched 2026-11-11)**
- The free license covers individuals, for-profit organizations with up to 3 employees, non-profits, and evaluation before commercial use. It allows commercial and non-commercial use "for creating videos and images." Anyone else needs a Company License. — [Remotion LICENSE.md](https://github.com/remotion-dev/remotion/blob/main/LICENSE.md)
- Company License pricing: "Remotion for Creators" is $25/month per seat (manual creation, local environment). "Remotion for Automators" is $0.01 per render with a $100/month minimum, and developers on automation projects need no seat. Enterprise starts at $500/month. — [remotion.pro/license](https://www.remotion.pro/license)
- A third-party article (2026-09-28) notes that seats are also needed for agent-written code, so a pipeline that uses Remotion under the hood (e.g. OpenMontage's default path) can trigger fees for teams of 4 or more. — [Capital & Compute](https://capitalandcompute.net/blog/claude-motion-graphics-tools/)
- Conflict: PkgPulse (2026-03-09) calls Remotion's license "Business Source License (BUSL)". — [PkgPulse](https://www.pkgpulse.com/guides/remotion-vs-motion-canvas-vs-revideo-programmatic-video-2026); contradicted by Remotion's own [LICENSE.md](https://github.com/remotion-dev/remotion/blob/main/LICENSE.md) and by [HeyGen's comparison](https://hyperframes.heygen.com/guides/hyperframes-vs-remotion), both of which describe Remotion's own source-available license. Treat "BUSL" as wrong.

### Inferences
- A single creator (an individual) falls under Remotion's free license for commercial reels. Fees apply only at 4 or more people, or for Automator-style render volume in a company context.
- Remotion's skill bundle grew from one `remotion-best-practices` skill with about 31 rules (January 2026) to 13 task-specific skills (November 2026). Older tutorials may reference commands that no longer match.
- Render time for a 60 s, 30 fps vertical clip (1,800 frames) depends heavily on the composition: video decode through `OffthreadVideo`, blur and shadow effects, and font loading. Measure locally rather than trusting any quoted number.

## Q2. HyperFrames (HeyGen): what it is, maturity, difference from Remotion, Claude Code skill support

### Takeaway
HyperFrames is HeyGen's Apache-2.0 "HTML → deterministic MP4" framework, released 2026-04-17. Agents write plain HTML/CSS plus a paused GSAP (or Lottie/WAAPI/Three.js) timeline. Headless Chrome seeks each frame and FFmpeg encodes. It has a first-party Claude Code plugin and is the de-facto choice for overlay-style graphics (captions, lower thirds, kinetic text), including transparent WebM output. It is young: packages are pre-1.0 (0.6.x) and Studio is marked "evolving".

### Cited Findings
- Tagline "Write HTML. Render video. Built for agents." Apache 2.0. The renderer seeks each frame in headless Chrome (Puppeteer) and encodes with FFmpeg, and the same input produces the same frames. Supported animation sources: GSAP, CSS animations, Lottie, Three.js, Anime.js, WAAPI and custom frame adapters. Requires Node.js 22+ and FFmpeg. The GitHub page showed 82.1k stars on 2026-11-11. — [GitHub heygen-com/hyperframes](https://github.com/heygen-com/hyperframes) (fetched)
- Star count growth: 53,647 on 2026-09-28 — [Capital & Compute](https://capitalandcompute.net/blog/claude-motion-graphics-tools/); 81.6K on the skills.sh listing — [skills.sh](https://www.skills.sh/heygen-com/hyperframes/claude-design-hyperframes); 82.1k on GitHub, 2026-11-11 — [GitHub](https://github.com/heygen-com/hyperframes)
- Release date 2026-04-17 under Apache-2.0, with no per-render fees. — [Cutback blog, 2026-11-06](https://cutback.video/blog/hyperframes-vs-remotion-vs-selects); also [themenonlab.blog](https://themenonlab.blog/blog/heygen-hyperframes-video-as-code) (snippet)
- Claude Code integration: `claude plugin marketplace add heygen-com/hyperframes`, then `claude plugin install hyperframes@hyperframes`. Standalone skills install with `npx skills add heygen-com/hyperframes` and update with `npx hyperframes skills update`. — [GitHub](https://github.com/heygen-com/hyperframes)
- The plugin has 21 skills, including a `/hyperframes` router. — [Capital & Compute, 2026-09-28](https://capitalandcompute.net/blog/claude-motion-graphics-tools/); also search summary of the [HyperFrames vs Remotion guide](https://hyperframes.heygen.com/guides/hyperframes-vs-remotion)
- Some skills (`/reverse-any-video`, `/style-sampling`) are tied to HyperFrames Pro. The Studio Pro plan adds HeyGen's premium models. Studio is marked "Available, evolving." — [GitHub](https://github.com/heygen-com/hyperframes)
- Maturity signal: the npm package `@hyperframes/producer` is at version 0.6.88 on jsDelivr. — [jsDelivr @hyperframes/producer@0.6.88](https://cdn.jsdelivr.net/npm/@hyperframes/producer@0.6.88/dist/transparency-test.d.ts)
- HeyGen's own comparison: Remotion asks for a React component, HyperFrames for an HTML file. In HyperFrames, markup declares when elements appear and a GSAP timeline declares how they move, with timing in seconds; in Remotion, timing is math in frames. HyperFrames pauses the animation and seeks it before each capture, so GSAP, WAAPI and Lottie render identically every time. The rules are a paused timeline, no wall-clock reads and no unseeded randomness, and violations "fail quietly." Both render on AWS Lambda; HyperFrames also renders locally, on HeyGen cloud and on Google Cloud Run. — [HyperFrames docs: vs Remotion](https://hyperframes.heygen.com/guides/hyperframes-vs-remotion) (vendor-authored, undated)
- When HeyGen says to choose Remotion: the team already writes React and wants to reuse components and charting libraries; it wants a simpler mental model with no timeline registration; it values more templates, tutorials, production history and mature Lambda rendering. — [HyperFrames docs](https://hyperframes.heygen.com/guides/hyperframes-vs-remotion)
- Migration skill: `npx skills add heygen-com/hyperframes --skill remotion-to-hyperframes`. It flags `useState`/`useEffect`, async metadata and third-party React UI libraries instead of mistranslating them, then renders both versions and compares them frame by frame. — [HyperFrames docs](https://hyperframes.heygen.com/guides/hyperframes-vs-remotion)
- Rationale given by HeyGen engineer James Russo (AI Engineer talk "HTML is all agents need"): agents already know web languages, while Remotion requires them to have learned a specific framework. — snippet via [ai.engineer talk page](https://ai.engineer/talks/html-is-all-agents-need)
- Mixed practitioner verdicts: one hands-on review (Woshipm, cited in a search summary) got better results from Remotion with the same prompts and attributed this to more Remotion training data. Moda's comparison describes a team concluding that switching renderers did not fix motion direction and pacing. — snippet via [moda.app](https://moda.app/blog/hyperframes-vs-remotion) (UNVERIFIED; page not fetched, Woshipm original not located)

### Inferences
- For the stated goal (effects over talking-head footage), HyperFrames' sweet spot (overlays, captions, lower thirds, kinetic text rendered with alpha) matches better than Remotion's "whole video as React" model. Remotion can still do it via `OffthreadVideo`.
- Because HyperFrames compositions are plain HTML, a design produced in Claude Design (which exports standalone HTML) or any web prototype can become a video with no React rewrite. HeyGen ships a skill for exactly this path (see Q5).
- The pre-1.0 versioning and seven months since release mean breaking changes are plausible. Pin versions in a workflow.

### Gaps
- No independent render-speed benchmark for HyperFrames on a 60 s 1080x1920 clip.
- No source found on HyperFrames CJK font handling (font embedding, Traditional Chinese line breaking).
- Official GitHub showed no release tags in the captured content, so the exact current version and changelog cadence are unverified.

## Q3. Other options: Motion Canvas, Revideo, Manim, Lottie/lottie-web, Rive, HTML/CSS/GSAP + Playwright/Puppeteer capture, After Effects scripting — agent-friendliness

### Takeaway
Anything that is plain text code with a deterministic time→frame function is agent-friendly: HTML/GSAP with seek-based capture (which is what HyperFrames productizes), Manim (Python), Motion Canvas and Revideo (TS generators). GUI-centric tools (After Effects, Rive, Cavalry, Jitter) are not, except through community MCP bridges or their own built-in agents. Motion Canvas and lottie-web show slowing maintenance.

### Cited Findings
- **Motion Canvas vs Revideo (PkgPulse, updated 2026-03-09):** both are MIT-licensed with TypeScript generator functions on a canvas engine (no full DOM). Motion Canvas is editor-first with no server rendering, about 8K weekly npm downloads, 16K+ stars and v3.x. Revideo is the Motion Canvas fork that adds a Node.js render API, batch rendering and a REST API; it has about 3K weekly downloads, 2K+ stars, is at v0.x, and its business model is hosted rendering at re.video. — [PkgPulse](https://www.pkgpulse.com/guides/remotion-vs-motion-canvas-vs-revideo-programmatic-video-2026)
- Revideo's docs say Motion Canvas maintainers do not intend it as a library, only as a standalone editor; this is why Revideo forked it. — snippet via [Revideo docs](https://docs.re.video/)
- Motion Canvas's last push was 2026-07-02. lottie-web has had no push to its default branch since 2025-09-01. — [Capital & Compute, 2026-09-28](https://capitalandcompute.net/blog/claude-motion-graphics-tools/)
- The same article ranks agent fit as follows. HyperFrames is first (official plugin, 21 skills, deterministic). Manim scenes are plain Python classes, "about the easiest thing" for Opus 5.5 to write and debug. Motion Canvas generators let an agent revise one beat without touching others. HTML/CSS is what the model has seen most, and the DOM is easy for an agent to inspect. Rive includes its own editor agent on every plan (Free, $9, $32, $120/seat/month). After Effects, Cavalry and Jitter have no Claude connector listed, and Anthropic's Adobe connector does not name After Effects. After Effects costs US$22.99/month. The article also notes that "timing to music is where most viral clips needed a human pass." It did not render or benchmark anything. — [Capital & Compute](https://capitalandcompute.net/blog/claude-motion-graphics-tools/)
- The same article classes Remotion and GSAP as "not open source". — [Capital & Compute](https://capitalandcompute.net/blog/claude-motion-graphics-tools/) (GSAP's license status was not independently verified here)
- **HTML/GSAP + Playwright/Puppeteer capture:** the pattern is to make the animation a pure function of time, then have Playwright seek to each timestamp (e.g. 1/60 s steps) and screenshot it, which avoids frames dropped by a real-time clock. — [yuv.ai "Motion in Code"](https://yuv.ai/blog/motion-in-code-claude-launch-films) (snippet). A variant pipes the PNGs to FFmpeg. — [help.apiyi.com](https://help.apiyi.com/en?p=34602) (snippet)
- The Playwright MCP can record browser sessions directly with `--save-video`, as listed in the Claude Code Video Toolkit. The same toolkit lists a Claude Code plugin for Manim covering planning, writing, rendering and iterating. — [wilwaldon/Claude-Code-Video-Toolkit (reader mirror)](https://hn.jakechampion.name/reader/https://github.com/wilwaldon/Claude-Code-Video-Toolkit) (snippet)
- **Lottie:** HyperFrames supports Lottie through an adapter with paused playback for frame-accurate seeking. — [vibeindex: hyperframes/lottie skill](https://www.vibeindex.ai/skills/heygen-com/hyperframes/lottie) (snippet). Third-party skills generate Lottie JSON with Claude Code: diffusionstudio/lottie ("Generate production-ready Lottie animations with Claude Code or Codex") — [gittrend](https://gittrend.io/repo/diffusionstudio/lottie) (snippet); iart-ai/web-animation-skills `lottie-animation` — [GitHub iart-ai/web-animation-skills](https://github.com/iart-ai/web-animation-skills) (snippet)
- **After Effects scripting via MCP:** Dakkshin/after-effects-mcp needs After Effects 2022+ and Node 14+ and ships a `.mcp.json` for Claude Code. Its MCP server writes queued commands to a file that an ExtendScript bridge panel (`mcp-bridge-auto.jsx`) polls, so the panel must stay open. The TheLlamainator fork adds effects, presets, keyframing, markers and audio-aware tools, and requires enabling script file/network access in After Effects. No 2026 release status was found. — [mcpservers.org: Dakkshin](https://mcpservers.org/ja/servers/Dakkshin/after-effects-mcp); [mcpservers.org: TheLlamainator](https://mcpservers.org/servers/thellamainator/after-effects-mcp) (aggregator listings)
- **Blender** has a first-party MCP connector (Blender 4.2+). Blender's own docs warn that it runs LLM-generated code "without any guards in place" and recommend a VM and working on a copy. — [Capital & Compute](https://capitalandcompute.net/blog/claude-motion-graphics-tools/)

### Inferences
- Revideo is the only Motion Canvas-family option with a headless render API. Its low adoption (about 3K weekly downloads) and v0.x status, plus Motion Canvas's slowing activity, make both riskier bets than Remotion or HyperFrames for a new workflow in late 2026.
- Hand-rolling HTML/GSAP + Playwright seek-capture duplicates what HyperFrames already does, with the determinism rules handled for you. It only makes sense if you want zero framework dependency.
- `--save-video` real-time recording is not frame-accurate, so it is unsuitable for final renders (it conflicts with the seek-based-capture rationale above).
- Manim is strong for math and diagram explainers but a poor fit for brand overlays on camera footage.
- After Effects via MCP is fragile (file-polling bridge, GUI app required) and costs a subscription. For a Claude Code-only workflow it is the least agent-friendly option.

### Gaps
- No source evaluating Rive specifically for agent-generated video overlays, and no source on Rive's video export.
- No source on Manim with Traditional Chinese text (Text vs LaTeX/ctex font configuration).
- Revideo's 2026 maintenance status was not confirmed from its GitHub commit history.

## Q4. Compositing over existing camera footage (alpha renders vs importing source video) and caption components

### Takeaway
There are two patterns. (a) Import the talking-head clip into the composition and render one final MP4: Remotion `<OffthreadVideo>` / `@remotion/media <Video>`, or HTML `<video>` in HyperFrames. (b) Render overlays with alpha and composite them with FFmpeg or an NLE (non-linear video editor such as Premiere or DaVinci Resolve): Remotion WebM VP8/VP9 `yuva420p` or ProRes 4444 `yuva444p10le`; HyperFrames `--format webm` VP9 `yuva420p`. Remotion's TikTok-style captions need space-delimited tokens, which Chinese text does not have natively.

### Cited Findings
**Remotion transparent rendering (official, fetched)**
- WebM: no background in the composition, image format `png`, codec `vp8` or `vp9`, pixel format `yuva420p`. The docs give this example command: `remotion render --image-format=png --pixel-format=yuva420p --codec=vp8 my-video video-transparent.webm`. Chrome and Firefox support WebM alpha, and the docs recommend rendering an opaque fallback too. — [Remotion docs: transparent videos](https://www.remotion.dev/docs/transparent-videos)
- ProRes 4444 for editors (Final Cut, Premiere, DaVinci): `--image-format=png --pixel-format=yuva444p10le --codec=prores --prores-profile=4444` (or `4444-xq`). Per-composition defaults can be set via `calculateMetadata`. — [Remotion docs: transparent videos](https://www.remotion.dev/docs/transparent-videos)
- Caveats: transparent WebM "can flicker at chunk boundaries" on Lambda, so the docs prefer ProRes there or a single-pass local render. `<OffthreadVideo>` needs the `transparent` prop to keep alpha, at a slight performance cost. `<Video>` from `@remotion/media` is recommended for embedding transparent videos. — [Remotion docs: transparent videos](https://www.remotion.dev/docs/transparent-videos)
- Importing source footage: the captioned talking-head pattern layers a captions component over `<OffthreadVideo src={staticFile('talk.mp4')}>`. — [mcp.directory](https://mcp.directory/blog/claude-remotion-skill-guide)

**HyperFrames transparent rendering (third-party readmes/guides; verify against official docs)**
- `hyperframes render . --format webm -o render.webm` keeps alpha. MP4 output is opaque. — snippet via [instagit: video-use + HyperFrames overlays](https://instagit.com/browser-use/video-use/integrate-hyperframes-html-css-gsap-overlays/)
- The producer readme says transparency comes from browser alpha, not chroma keying. WebM is VP9 `yuva420p` and plays as an overlay in Chrome, Edge and Firefox. "Safari + WebM alpha is incomplete", and a MOV (ProRes 4444) export is suggested for editors. — snippet via [pkgstats @hyperframes/producer](https://www.pkgstats.com/pkg:@hyperframes/producer)
- `hyperframes remove-background` turns an existing video into a transparent WebM, downloading model weights on first run. — snippet via [pkgstats @hyperframes/producer](https://www.pkgstats.com/pkg:@hyperframes/producer) (UNVERIFIED against official docs)
- The official GitHub README mentions only MP4 output explicitly. — [GitHub heygen-com/hyperframes](https://github.com/heygen-com/hyperframes)
- Editor caveat: a Shotcut forum thread reports that overlaying clips in the timeline disables the alpha channel of a WebM VP9 alpha file. — snippet via [Shotcut forum](https://forum.shotcut.org/t/alpha-channel-lost-on-export/22991)

**Captions**
- `@remotion/captions` → `createTikTokStyleCaptions({ captions, combineTokensWithinMilliseconds, breakOnSilenceAfterMilliseconds? })` returns `{ pages }`. Each page has `text`, `startMs`, `durationMs` and `tokens`, and each token has `text`, `fromMs`, `toMs` and `pageBreakAfter`. Word highlighting works by animating each token by its absolute `fromMs`/`toMs`. A low `combineTokensWithinMilliseconds` gives word-by-word display. Available from v4.0.216. — [Remotion docs: createTikTokStyleCaptions](https://www.remotion.dev/docs/captions/create-tiktok-style-captions)
- Whitespace rule: each token's `text` must include a leading space, because spaces are the delimiters. Without them the text merges into one line or page. Render with `white-space: pre`. The page does not discuss Chinese or Japanese. — [Remotion docs: createTikTokStyleCaptions](https://www.remotion.dev/docs/captions/create-tiktok-style-captions)
- Remotion ships a `/remotion-captions` agent skill. — [Remotion docs: Agent Skills](https://www.remotion.dev/docs/ai/skills)
- davila7/claude-code-templates' Remotion skill includes reference docs for TikTok-style pages with word highlighting and for importing `.srt` via `@remotion/captions`. — snippet via [claudemarketplaces.com](https://claudemarketplaces.com/skills/davila7/claude-code-templates/remotion)
- HyperFrames has no dedicated captioning API. Captions appear as use cases ("kinetic captions"), as a caption reference inside the `/hyperframes` skill, and as caption blocks in its catalog. — [GitHub heygen-com/hyperframes](https://github.com/heygen-com/hyperframes)

### Inferences
- For a 1080x1920 talking head, pattern (a) (import the footage and render once) avoids alpha-codec pitfalls but re-encodes the camera footage through headless Chrome, which is slower. Pattern (b) (alpha overlay, then `ffmpeg overlay` on the original) keeps the camera encode path separate and lets overlays be re-rendered alone. The ProRes 4444 path is the safest for NLE import, and WebM VP9 alpha is fine for an FFmpeg composite.
- Chinese captions with `createTikTokStyleCaptions`: Whisper-style Chinese output has no spaces. The workflow must pre-tokenize (per character or per word segment, e.g. with a word segmenter) and insert leading spaces or zero-width delimiters, or else build its own token→page logic. This is an inference from the whitespace rule. No source documents a CJK recipe.

### Gaps
- No primary documentation found on how HyperFrames handles an imported `<video>` element (decode accuracy, audio passthrough) for a full talking-head composite.
- No source covering Chinese word-level timestamps feeding `@remotion/captions` (e.g. Whisper/whisper.cpp output for Mandarin).

## Q5. Claude Design (Anthropic Labs, 2026): outputs, export/handoff to Claude Code, use for video-overlay brand systems

### Takeaway
Claude Design launched 2026-04-17 as an Anthropic Labs research preview powered by Opus 4.7. It produces designs, prototypes, slides, one-pagers and social assets, extracts a design system from the codebase and files, and exports HTML/PDF/PPTX/Canva or a handoff bundle to Claude Code. Claude Code now has a `/design` command and `/design-sync`. Per the help center, the standalone claude.ai/design closes on 2026-12-14. Animation lives in a separate "Claude Motion" beta (Team/Enterprise, MP4-only export). ## Q6. Concrete examples (repos, templates, posts) and reported failure modes; CJK font handling

### Takeaway
Working examples exist for Remotion + Claude Code (captioned vertical clips, Douyin-style ranking videos, full YouTube-edit pipelines) and for HyperFrames overlays inside larger pipelines. Reported failure modes cluster around: CSS/wall-clock animations that silently render static or non-deterministic; Remotion CJK font subset loading (bug fixed May 2026); fonts present in preview but missing in render; slow, memory-heavy renders; skill/version drift; and pacing and music timing that still need human passes. Token cost is rarely quantified.

**Failure modes**
- CSS transitions, `@keyframes` and Tailwind `animate-*` render static in Remotion, because each frame is captured frozen; animation must come from `useCurrentFrame()`. Inside `<Sequence>`, `useCurrentFrame()` resets to 0, so the offset must not be subtracted manually. Composed `transform` strings are not editable in Studio. — [mcp.directory, updated June 2026](https://mcp.directory/blog/claude-remotion-skill-guide)
- In HyperFrames, determinism rules (paused timeline, no wall-clock reads, no unseeded randomness) "fail quietly" when violated. — [HyperFrames docs](https://hyperframes.heygen.com/guides/hyperframes-vs-remotion)
- Renders are slow and memory-intensive (8 GB+ RAM recommended), the first render waits for the Chromium download, the skills version must match the Remotion version, and AI code "may need minor adjustments — don't blindly trust everything." — [heyuan110.com](https://www.heyuan110.com/posts/ai/2026-01-26-claude-code-remotion-video/)
- Editors who tried "Claude + Remotion" for cutting interview footage found it "completely useless" (vendor-framed claim). — [Cutback blog, 2026-11-06](https://cutback.video/blog/hyperframes-vs-remotion-vs-selects)
- "Timing to music is where most viral clips needed a human pass". The viral examples are self-reports, not measurements. — [Capital & Compute, 2026-09-28](https://capitalandcompute.net/blog/claude-motion-graphics-tools/)
- Claude Motion: longer or more complex animations consume more of the plan's usage limit than a typical message. — [Claude Help Center: Claude Motion](https://support.claude.com/en/articles/17454997-get-started-with-claude-motion)

**CJK / Traditional Chinese font handling**
- Remotion issue #7258 (opened 2026-05-04, closed 2026-05-05 via PR #7260): `@remotion/google-fonts` `loadFont()` threw on every CJK named subset (`chinese-simplified`, `chinese-traditional`, `chinese-hongkong`, `japanese`, `korean`), affecting about 120 fonts, tested on 4.0.454. Root cause: Google Fonts serves CJK as about 100 numbered unicode-range chunks per weight, not as named subsets. The issue page does not state the release version that contains the fix. — [GitHub remotion-dev/remotion#7258](https://github.com/remotion-dev/remotion/issues/7258)
- Remotion Lab (a Traditional Chinese troubleshooting site) says `@remotion/google-fonts` loading can time out, and recommends loading only the `chinese-traditional` subset and only the needed weights. — snippet via [remotionlab.pages.dev](https://remotionlab.pages.dev/docs/font-loading-errors)
- Fonts that work in preview can vanish in the render if not loaded correctly. System fonts available on macOS may not exist in headless Chrome on Linux render servers. Fix: bundle the font and load it with `@font-face` via `staticFile()` or `@remotion/fonts`, and do a 10-second test render first. — snippet via [crepal.ai](https://crepal.ai/blog/aivideo/blog-how-to-use-custom-fonts-in-remotion/) (secondary)
- Full CJK font coverage typically runs 5–30 MB, so a fallback chain of several CJK fonts is expensive. — snippet via [unicodefyi glossary](https://unicodefyi.com/vi/glossary/font-fallback/) (generic, low-authority source)
- A counterpoint from January 2026: a Simplified Chinese Douyin build with `@remotion/google-fonts/NotoSansSC` reported no rendering problems ("any font you load will work"). — [heyuan110.com](https://www.heyuan110.com/posts/ai/2026-01-26-claude-code-remotion-video/) (this predates issue #7258, so a different import path or version may explain the difference)

### Inferences
- For Traditional Chinese overlays, the most robust approach in either framework is a locally bundled, subset TC font (e.g. a Noto Sans TC or Taiwan-licensed font subset to the glyphs used) loaded via `@font-face`/`staticFile()`, with an explicit "fonts ready" wait before capture. This avoids Google Fonts chunking, network timeouts and render-machine font differences.
- Agent-specific risk: Claude tends to write CSS keyframe or Tailwind animations by habit. In Remotion these silently render static; in HyperFrames, wall-clock code fails quietly. A skill or lint step that enforces the framework's timing model is therefore the main quality lever.
