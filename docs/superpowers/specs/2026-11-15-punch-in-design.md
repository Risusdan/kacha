# 推近設計

- 日期：2026-11-15
- 狀態：待審閱（使用者授權：設計、計劃、實作都由 Claude 自己審，合併前停下來問）
- 依據：
  - 原設計 `docs/superpowers/specs/2026-11-11-reels-workflow-design.md` 第 8.6 節：推近放在同一個口播鏡頭的切點後，預設放大 1.1 倍，上限 1.2 倍，以臉部偵測框中心為錨點；
  - 使用者 2026-11-15 的選擇：第 2 期先做推近；推近預設在每個剪接點，在原尺寸和放大之間交替，想要哪裡不推、哪裡推大一點，跟 Claude 說。
  - 使用者同一天看了 test001 的示範之後改變決定：每個剪接點都換景別太頻繁，一個人靜靜對著鏡頭講話的素材配起來不自然。改成預設不推近，只在使用者指定的地方推近。
- 範圍：第 2 期的第一個子項目。動畫（Remotion）、B-roll、音效和音樂不在這裡。

## 1. 目標

口播剪掉贅字和停頓之後，前後兩段畫面幾乎一樣，接起來會「跳」一下（跳接）。推近在剪接點把畫面放大，讓那一次跳接看起來是刻意換了景別，也能用來強調一句話。只在使用者要的地方推近。

成功的樣子：

- 不寫任何設定，輸出的成品和第 1 期一樣，整支都是原尺寸；
- 使用者說「0:42 那句放大」或「那裡放大多一點」，Claude 改 `edit.json` 就能改；
- 放大時，臉留在畫面上原來的位置，四周往外推；
- 同意之前，分鏡稿和審閱頁看得到哪裡推近、推多少。

## 2. 名詞

- **片段**：成品裡連續的一段原始畫面，也就是 `edit.build_segments` 給的一個 `Segment`。
- **剪接點**：兩個相鄰片段接起來的地方。
- **倍數**：片段放大的比例。1 是原尺寸，1.1 是放大 1.1 倍。
- **基準畫面**：原始畫面置中裁成 9:16 的範圍。這是第 1 期輸出的畫面，倍數 1 的片段照這個範圍輸出。
- **錨點**：放大時不動的那一點，用基準畫面裡的 0 到 1 座標表示（左上是 0, 0）。

## 3. 每個片段的倍數

### 3.1 預設：不推近

- 每個片段都是 1。
- 例外：`punch_in` 沒寫到的片段短於 1 秒時，沿用前一個片段的倍數，不換景別。
  - 原因：第一支真實影片（test001）有 23 個片段，其中兩個只有 0.07 秒和 0.13 秒（2 格和 4 格）。放大的片段後面接著這種短片段時，如果短片段縮回原尺寸，下一個片段又是另一個景別，畫面會在一兩格裡換兩次景別，看起來像閃了一下。

### 3.2 使用者改的：`punch_in`

`edit.json` 加一個可以省略的鍵 `punch_in`：句子代號對到倍數。

```json
"punch_in": {"s07": 1.1, "s12": 1.2}
```

- 意思：從這一句開始的片段，倍數用這個值。一句裡可能開始好幾個片段，全部都用這個值。其他片段照 3.1。
- 「從這一句開始」：片段的起點落在這一句的範圍裡（`trim.json` 的 `bounds`，從 `cut_in` 到 `cut_out`）。起點落在兩句之間的空檔，算下一句。
- 倍數是數字，1 到 1.2（含）。1 就是不推。使用者沒說倍數時，Claude 寫 1.1。
- `validate` 擋下這些錯誤：
  - 代號不是講者有講的句子；
  - 倍數不是數字，或不在 1 到 1.2 之間。
- 這一句被 `cuts.extra` 拿掉，或沒有任何片段從它開始（整句落在一個片段的中間）：這一筆留著、不起作用，`validate` 照樣通過，結果的 `warnings` 列出它（`punch_in.<代號>: no shot starts in this sentence, so it changes nothing`）。不擋下，是因為審閱頁切換剪接或拿掉一句時不改 `punch_in`：擋下的話，頁面上的改動會被拒絕，使用者在頁面上無從修。和 `captions.text` 對拿掉的句子的做法一樣。
- 使用者說的是時間（「0:42 那裡」），Claude 先寫那個時間在講的句子，跑 `validate` 和 `storyboard`，看推近欄列出的那段有沒有包含那個時間。沒有，表示那個時間播的片段從更前面的句子開始（片段可能從一句的中間開始，也可能延到下一句），就把這一筆移到前一句保留的句子，直到包含為止。放大的是整個片段，可能比那一句早開始或晚結束；Claude 照推近欄告訴使用者實際放大的時間。

### 3.3 版本

`edit.json` 的 `version` 仍是 1：`punch_in` 是可以省略的鍵，舊的 `edit.json` 照樣通過。第 1 期的 `validate` 把 `punch_in` 當成之後期別的鍵擋下；這次改成接受。

## 4. 錨點

- 每個片段用自己的錨點，整個片段不動（不跟著臉移動，避免畫面晃）。
- 找法，依序：
  1. 這個片段的原始時間裡，`faces.json` 取樣到的臉，取它們中心點的中位數；
  2. 片段裡沒有取樣到臉：取時間上離片段中點最近的一個臉；
  3. 整支都沒有偵測到臉：用基準畫面的正中央。
- 臉的座標是整個原始畫面的 0 到 1。換成基準畫面的座標之後，落在基準畫面外面的，移到最近的邊上。
- 放大 s 倍時，輸出的範圍是基準畫面裡寬、高都是 1/s 的一塊，位置讓錨點留在畫面上原來的位置：左邊 = 錨點 x × (1 − 1/s)，上邊 = 錨點 y × (1 − 1/s)（以基準畫面的寬高為 1）。這一塊一定在基準畫面裡面。
- test001 的臉靠畫面左邊（中心 x 約 0.18、y 約 0.43），臉的左半邊在畫面外。用固定點放大，臉不會被拉到畫面中間，畫面只是往外推。

## 5. 輸出

現在的濾鏡串：

```text
setpts → fps=30 → select（留下片段的格）→ setpts=N/30/TB → scale（蓋滿 1080×1920）→ crop（置中 1080×1920）→ subtitles → format
```

改成：

```text
setpts → fps=30 → select → setpts=N/30/TB → crop（原始畫面裡的基準畫面）→ zoompan（逐格的倍數和位置，輸出 1080×1920）→ subtitles → format
```

- `crop` 從原始解析度裁出基準畫面（9:16，置中），大小是偶數像素。
- `zoompan` 的 `d=1`、`fps=30`、`s=1080x1920`。`z`、`x`、`y` 是以輸出格的編號 `on` 寫成的分段式：每個片段一項 `gte(on,A)*lt(on,B)*值`，加起來；項目多時照 `select` 的做法用平衡樹加總，避免運算式太深。
- 每一格只縮放一次（`zoompan` 從基準畫面裁出那一塊，直接縮到 1080×1920），符合原設計「每個來源只縮放一次」。
- 實測（ffmpeg 9.0.2，合成畫面）：選格之後接 `zoompan`，60 格進、60 格出；`on` 從 0 開始；視窗左上角照 `x`、`y` 的值放。
- 字幕在 `zoompan` 之後才燒進去，位置不受推近影響。
- `render` 讀 `work/faces.json`。`faces.json` 是 `prep` 的輸出；`prep` 重跑，後面的步驟和關卡 1 的同意本來就要重來，不用另外記。
- 手機預覽版從成品縮小，推近跟著在裡面。

## 6. 分鏡稿和審閱頁

- **分鏡稿**（`storyboard`，網頁和 `storyboard.md`）：句子表加一欄「推近」，列出從這一句開始、有放大的每個片段在成品裡從幾秒到幾秒、放大幾倍，例如「0:02.8 到 0:05.1 放大 1.1 倍」（倍數照 `edit.json` 寫的數字）。沒有的話空白。摘要加一行：剪接點幾個、放大的片段幾個。
- **審閱頁**：播放時照目前播到的片段，把影片畫面用同樣的倍數和錨點放大（CSS 的 `transform`），所以同意之前看得到推近的樣子。審閱頁不改推近：要改，在對話裡跟 Claude 說。
- 推近的倍數只由 `edit.json`、`transcript.json`、`trim.json` 決定，這三個檔案本來就綁在關卡 1 的同意上；錨點來自 `faces.json`（`prep` 的輸出）。所以同意綁的東西不用加。這次之前同意過的專案，`edit.json` 沒有 `punch_in`（第 1 期的 `validate` 擋下這個鍵），成品照樣不推近，舊的同意照樣算數。

## 8. 測試

行為的改動先寫會失敗的測試。範例句子一律自己編。

- 倍數：不寫 `punch_in` 每段都是 1、`punch_in` 只改從那一句開始的片段、放大的片段後面短於 1 秒的片段沿用、一句裡開始好幾個片段。
- 片段屬於哪一句：起點在句子範圍裡、在兩句之間的空檔、第一個片段。
- 錨點：片段裡有臉取中位數、沒有就取最近的、整支沒有臉用正中央、橫式畫面置中裁切後換算、超出基準畫面移到邊上、輸出範圍一定在基準畫面裡。
- `validate`：接受 `punch_in`；擋下不存在或沒講到的句子、不是數字、超出 1 到 1.2；被拿掉或沒有剪接點的句子通過，列在 `warnings`；審閱頁上讓一筆不起作用的改動照樣存得進去。
- 輸出：濾鏡串的樣子；用合成畫面跑真的 ffmpeg，確認放大的片段那幾格是預期的那一塊，其他格是原尺寸；格數不變。
- 分鏡稿：推近欄和摘要。
- 審閱頁：資料裡每個片段的倍數和錨點；播放時套用的 `transform`（Node 測試）。

## 9. 決定紀錄

Claude 自己決定的，使用者合併前可以推翻：

| 決定 | 為什麼 | 錯了的代價 |
|---|---|---|
| 原設計「相鄰兩次推近不用同一個倍數」不用 | 推近只在使用者指定的地方，倍數也由他決定 | 使用者想要每次推近的倍數不一樣：Claude 寫不同的數字就好 |
| 放大的片段後面短於 1 秒的片段不換景別 | 避免畫面閃一下（3.1） | 1 秒太長或太短：改一個常數 |
| 錨點是固定點放大，不把臉移到中央 | 臉留在原位，畫面只是往外推，最不突兀 | 使用者想把臉放到中央：改 4 的算法 |
| 一個片段一個錨點，不跟著臉移動 | 不晃；臉的取樣大約 2 秒一次，跟著動也不準 | 講者在一個長片段裡移動很多：之後再加平滑追蹤 |
| `punch_in` 用句子代號，不用剪接點編號 | 剪接點是從剪掉的段落推出來的，剪接一改就重新編號；句子代號不會 | 一句裡有好幾個剪接點、只想改其中一個：目前做不到，要改成更細的位置 |
| 審閱頁只預覽推近，不能在頁面上改 | 範圍小；改推近的情況少，用講的就夠 | 使用者常常要改：之後在頁面上加 |
| 輸出時的基準畫面，用 `render` 讀的那支影片的實際尺寸算（`ffprobe`），不用 `probe.json` 的尺寸 | HDR 素材讀的是 `prep` 轉出的 SDR 副本，比原始影片小（例如原始 2160×3840，副本 1350×2400）；臉的座標是 0 到 1，兩種尺寸都對得上 | 多一次 `ffprobe`，約零點幾秒 |
| 窗格的左上角取最近的偶數像素 | yuv420 每 2×2 像素一個色度樣本，`zoompan` 本來就會把奇數往下移；先取最近的偶數，錨點偏不到 1 個像素 | 無 |
| `render` 把 `faces.json` 列為輸入，輸出的版本改成 3 | 成品的畫面跟著 `faces.json` 變；濾鏡串換了，版本號讓 `status` 和 `render` 都知道要重做 | 已經輸出過的專案，`status` 會回到 `render`，不用重新同意；沒有 `punch_in` 的，重新輸出的畫面和原來一樣 |
| 分鏡稿不加版本，同意也不記分鏡稿的版本 | 預設不推近，沒有 `punch_in` 的成品和以前一樣；舊的同意不會讓 `render` 輸出使用者沒看過的推近（6） | 之後分鏡稿多了會改變成品、預設就有的東西（例如動畫）時，要加上版本 |
| `punch_in` 指到被拿掉、或沒有片段開始的句子：通過，列在 `warnings`（3.2） | 審閱頁切換剪接時不改 `punch_in`；擋下的話，頁面上的改動會被拒絕，使用者在頁面上無從修 | 一筆不起作用的設定留在 `edit.json` 裡；Claude 下次 `validate` 時看到警告再處理 |
| 推近欄寫出每個放大片段在成品裡從幾秒到幾秒（6） | 放大的是整個片段，可能從一句的中間開始，也可能延到下一句；使用者要知道實際放大的地方 | 無 |
| 4K 素材的速度 | 實測（合成的 2160×3840 畫面，20 秒）：舊的濾鏡串 3.1 秒，新的 3.2 到 3.4 秒 | 無 |

## 10. 不做的事

- 推近的動畫（慢慢放大）：只做剪接點上的瞬間換景別。
- 跟著臉移動的追蹤。
- 在審閱頁上改推近。
- 自動挑推近的位置（例如重點句）：使用者選了只在他指定的地方推近。
