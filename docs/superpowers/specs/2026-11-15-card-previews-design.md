# 卡片樣張：同意之前看得到卡片的樣子（2026-11-15）

動畫卡片（`docs/superpowers/specs/2026-11-15-remotion-foundation-design.md`，下稱地基；`2026-11-15-three-more-cards-design.md`）現在只在成品裡看得到。審閱頁播到卡片的時段，只在影片上方標一行卡片的名稱和字；手機用的分鏡稿網頁（`review/gate1/index.html`）只有文字。卡片的大小、放在哪一邊（避開頭）、字排起來的樣子，使用者要等 `render` 做完才看得到；看了想改，就要改、重新同意、再輸出一次。

這一份讓使用者在關卡 1 同意之前，就看到每張卡片的樣張。原始設計（`2026-11-11-reels-workflow-design.md`）的關卡 2「樣張」是另一道關卡；這裡不加關卡，把卡片的樣張放進關卡 1 的兩個頁面。

## 1. 範圍

- 每段會出現的動畫（`scenes.scene_layout` 裡 `gone` 是 `None`、`frames` 大於 0 的）有一張樣張。
- 樣張是卡片停住時的樣子：進場做完、還沒開始退場的那一格。動畫本身照舊只在成品裡看得到。
- 卡片放在 `render` 會放的位置（中間、靠左或靠右，地基 9.1），所以樣張也看得出卡片有沒有蓋到頭。
- 不做：會動的預覽、推近的樣張（審閱頁已經照實際的樣子播推近）、字幕畫進樣張、新的關卡。

## 2. 卡片的靜態圖

`render` 用的卡片影片（`work/scenes/<雜湊>.mov`）之外，多一種檔案：卡片的靜態圖，`work/scenes/<雜湊>.png`。

- 1080×1920 的透明 PNG，和成品的畫面一樣大，卡片畫在它在畫面上的位置；卡片以外全透明。
- 用 Remotion 的 `renderStill` 畫：同一個卡片元件、同樣的參數和位置（`align`），長度固定 90 格（`STILL_FRAMES`），畫第 81 格（`STILL_FRAME`，90 格的卡片退場前的最後一格）。六張卡在這一格都已經停住：長條圖的數字在第 46 格出齊，清單最後一個勾在第 51 格畫完。
- 停住的樣子和卡片實際有幾格無關，所以靜態圖的雜湊不含格數：卡片、參數、位置、風格（`style_digest`）、卡片原始碼（`sources_digest`），加上 `STILL_FRAMES` 和 `STILL_FRAME`。剪接改了、卡片的長度跟著變，靜態圖不用重畫；位置變了才要。
- `scenes/render.mjs` 多一種工作：`{"kind": "still", "card", "params", "frames", "frame", "align", "out"}`，`out` 以 `.png` 結尾。先寫在暫存資料夾（`TMPDIR`）裡的 `<檔名>.part.png`，寫完才改名成 `out`，印一行 `{"ok": true, "card", "out", "frame"}`。不像影片寫在 `out` 旁邊：兩次執行同時畫同一張靜態圖時（審閱頁和 `storyboard`），共用的暫存檔名會讓一方把另一方的檔案改名走，自己改名時找不到檔案而失敗（實測：4 個同時跑、5 輪，20 次裡 7 次）。沒有 `kind` 的工作照舊是影片。
- `pipeline/scene_render.py` 的 `render_stills(p, placed, style)`：缺的靜態圖一次畫完（一次 node、一次打包），回傳每段動畫和它的靜態圖。一次最多跑 120 秒（`STILLS_TIMEOUT_S`）：審閱頁的請求在等它，通常幾秒就完成。實測：打包約 0.4 秒、開瀏覽器約 0.35 秒、每張 0.35 到 0.6 秒。
- 畫之前的檢查和 `render_scenes` 一樣：卡片字型畫不出來的字、node、`scenes/node_modules`、Remotion 的瀏覽器。不過的話拋出 `PipelineError`，訊息也一樣。
- 暫存資料夾：每次各開一個 `work/scenes/still-tmp-<亂碼>`，做完用 `safe_rmtree` 刪掉；開始時，先刪掉 1 小時以前留下的 `still-tmp-*`（上次中斷留下的）。`render` 自己的 `work/scenes/tmp` 不動，所以審閱頁畫靜態圖和 `render` 同時跑也不會互刪。工作清單和靜態圖的暫存檔寫在暫存資料夾裡，記錄檔是 `work/stills.log`。
- `render.mjs` 打包時不用打包工具的快取（`enableCaching: false`），影片和靜態圖都是。快取放在 `scenes/node_modules/.cache`，所有專案共用；兩次執行同時寫它，打包工具會讓其中一次當掉（實測：有快取時 6 個同時跑，每輪 1 個當掉；快取是空的時，4 個裡 2 個）。不用快取，單跑一次反而比較快（實測 1.7 秒，用快取 2.3 秒）。

## 3. 分鏡稿網頁

- 摘要、警告和兩個清單之後、句子表之前，多一節「動畫的樣子」。每段動畫一張樣張，下面一行寫卡片的名稱、字和成品裡的時間，和句子表「動畫」欄的寫法一樣（「數字卡：兩小時／一天多撐（0:12.0 到 0:14.5）」），照動畫出現的先後排。沒有動畫的影片沒有這一節。
- 樣張是一張 540×960 的 JPEG，嵌在網頁裡：
  - 背景是那段動畫在成品裡正中間那一刻的原始畫面，照成品的取景裁切：9:16 的基本畫面，那一刻的鏡頭有推近的話照推近放大（`punch.base_window`、`punch.window`）。
  - 上面疊卡片的靜態圖。
  - 字幕不畫。這一節的開頭用一句話說明：樣張是卡片停住時的樣子，背景是那段動畫中間的畫面，字幕沒有畫上去。
- 網頁寬 640 px 以下時一欄，比較寬時一列排幾張，每張最寬 270 px。
- 卡片的位置要用臉的位置算（`card_place.placed_scenes`），樣張又是用卡片的原始碼畫的，所以有動畫出現時，`work/faces.json` 和卡片的原始碼（`scene_render.source_inputs`，和 `render` 的一樣）都是分鏡稿的輸入：任何一個變了，分鏡稿要重做、重新同意，和 `render` 一樣。沒有動畫出現時兩者都不讀。
- 樣張背景那一格：成品是各段鏡頭接起來的，每段的格數和 `render` 的 `select` 留下的一樣（`round(end × 30) − round(start × 30)`）；動畫正中間那一格（開始的格數加上格數的一半，取整數）落在哪段鏡頭，就用那段鏡頭的原始畫面和取景（`storyboard.reel_frame_source`、`storyboard.preview_crop`）。
- 靜態圖畫不出來時（缺 node、字型畫不出某個字、Remotion 出錯、讀寫檔案出錯），分鏡稿照樣做，沒有「動畫的樣子」這一節，結果的 `warnings` 多一則 `card previews not made: <原因>`，網頁的警告寫中文：「動畫卡片的樣張做不出來：<原因>」。原因通常也會讓 `render` 失敗（缺工具、字型畫不出某個字），所以這也是提早的警告。
- 樣張要用的靜態圖在 `work/scenes/` 裡缺了（上次畫不出來，或被刪了），或有動畫出現、網頁卻沒有「動畫的樣子」（做網頁時畫不出來，之後審閱頁畫好了）時，`storyboard` 不跳過，照樣重做：結果的 `warnings` 才會和網頁上的一致。靜態圖不算分鏡稿的輸出，所以缺了不會讓 `approve` 拒絕。
- 從原始畫面裁切、疊上卡片用 ffmpeg，和縮圖一樣；ffmpeg 失敗就和縮圖失敗一樣，分鏡稿拒絕。
- `storyboard.md` 不變：它是給 Claude 引用的文字，沒有圖。

## 4. 審閱頁

- 播到動畫的時段，卡片的靜態圖疊在影片上（和影片一樣大，不跟著推近縮放，和成品一樣：卡片疊在推近之後）。有靜態圖時，原本那行卡片名稱不顯示；沒有靜態圖時照舊顯示那一行。靜態圖載入完成才顯示（換成下一張時，載入之前不會顯示上一張）；載入失敗的，那段動畫照舊顯示卡片名稱。
- `GET /api/data` 的 `scenes` 每段多一個 `still`：靜態圖的網址（`scene-stills/<雜湊>.png`），檔案還沒有時是 `null`。卡片的位置照現在的剪接算：審閱頁上切換剪掉或保留，卡片的位置可能變。
- 伺服器在回 `/api/data` 之前，先把缺的靜態圖畫好（一次 node，約 2 秒），同一時間只畫一次（另一個請求等它畫完）。`render_stills` 有一張畫不出來就整次失敗，所以一次畫好幾張失敗時，再一張一張各畫一次。單獨畫也畫不出來的，寫進 `work/review.log`，那段動畫的 `still` 是 `null`，頁面照舊顯示卡片名稱；同一次審閱頁裡，這幾張不再重試。畫的時候讀寫檔案出錯也一樣處理，不讓 `/api/data` 失敗。
- `pipeline review` 開始提供審閱頁之前，先把靜態圖畫好，第一次打開就看得到；畫不出來一樣只寫記錄檔。
- `GET /scene-stills/<雜湊>.png` 回 `work/scenes/` 裡那個檔案。雜湊必須是 64 個小寫十六進位字，其他的一律 404；和其他路徑一樣要通行碼。

## 5. 文件

- `storyboard` skill「scenes：動畫」：審閱頁和網頁怎麼顯示卡片；字型畫不出來的字，現在做分鏡稿時就會警告。
- `reel` skill：警告表加 `card previews not made:`；第 316 行「審閱頁…不播真的動畫」改寫。
- `docs/features.md`、`README.md`：審閱頁和分鏡稿網頁看得到卡片的樣子。
- `FEATURE.md`：已完成加樣張；待開發的「關卡 2」改成只剩有聲預覽。

## 6. 測試

行為的改動先寫會失敗的測試。

- 靜態圖的雜湊：不含格數；卡片、參數、位置、風格、原始碼任何一個變了，雜湊就變。
- `render_stills`：只畫缺的；工作清單的內容；node 失敗時拋出 `PipelineError` 並附記錄檔；暫存資料夾刪掉、舊的 `still-tmp-*` 清掉、新的留著。用假的 `run`，不跑 node。
- 真的渲染（`tests/test_scene_cards.py`）：每張卡的靜態圖是 1080×1920、有透明；卡片的不透明範圍和同一張卡的影片在第 81 格的一樣（差不到 2 px）；靠邊的卡片貼著那一邊。
- 分鏡稿：有動畫時網頁有「動畫的樣子」和每段一張圖、圖的大小是 540×960；靜態圖畫不出來時有警告、沒有這一節，分鏡稿照樣做出來；有動畫時 `faces.json` 是輸入，沒有動畫時不是。樣張的背景用那段動畫正中間那一刻的鏡頭取景。
- 審閱頁：`/api/data` 的 `still`；缺的先畫、畫不出來是 `null` 而且不重試；一張畫不出來不擋其他張；`/scene-stills/` 的路徑擋下不合格的名字；頁面在動畫時段顯示靜態圖、沒有時顯示名稱；靜態圖載入完才顯示、載入失敗顯示名稱（node 測試）。
- 真的執行 `render.mjs`：不寫 `scenes/node_modules/.cache`；靜態圖旁邊另一次執行的暫存檔不被改名、覆蓋或刪掉。

## 7. 決定紀錄

| 決定 | 理由 | 錯了的代價 |
|---|---|---|
| 樣張放進關卡 1，不另開關卡 2 | 使用者已經在關卡 1 看剪接、看字幕；多一道關卡就多一次來回 | 之後想在樣張之後再確認一次成品：關卡 3 的事 |
| 靜態圖是整個畫面大小、卡片畫在它的位置 | 位置由 Remotion 自己排，不用另外算座標；審閱頁直接疊、分鏡稿直接 `overlay` | 一張約 65 KB，比只裁卡片大一些 |
| 卡片停住的那一格，不做會動的預覽 | 透明的影片在 Safari 和 Chrome 要不同格式；樣張的目的是看大小、位置和字 | 使用者想先看動畫：之後做有聲預覽時一起處理 |
| 審閱頁在回資料之前畫缺的靜態圖 | 畫一次約 2 秒，切換剪接很少改到卡片位置；不用另外讓頁面輪詢 | 卡片很多又常改位置時，頁面要等幾秒 |
| 靜態圖畫不出來只是警告 | 樣張是預覽，不該讓使用者連剪接都看不到 | 使用者沒看到樣張就同意：警告寫在網頁和 Claude 的訊息裡 |
| 有動畫時 `faces.json` 才是分鏡稿的輸入 | 卡片位置看臉；沒有動畫時臉的位置不影響分鏡稿，舊專案不用重新同意 | 之後分鏡稿別的地方也用到臉：改成一律是輸入 |
| 有動畫時卡片的原始碼也是分鏡稿的輸入 | 樣張是用它畫的；分鏡稿用到的檔案改了就要重新同意（`CLAUDE.md`） | 改卡片的程式之後，有動畫的專案要重新同意一次 |
| 缺靜態圖時 `storyboard` 不跳過，但靜態圖不是輸出 | 跳過時結果的 `warnings` 會少了樣張的警告；當成輸出的話，畫不出來會讓 `approve` 拒絕，違反「只是警告」 | 缺 node 時每次 `storyboard` 都重做縮圖和試聽片段，多幾秒 |
| 一次畫好幾張失敗時，審閱頁再一張一張各畫一次 | `render_stills` 有一張畫不出來就整次失敗；不重畫的話，一張的錯會讓其他張整個審閱頁都看不到 | 好幾張都畫不出來時，多跑幾次 node，每次約 2 秒 |
| 打包不用快取 | 所有專案共用一份快取，同時打包會當掉；不用快取反而比較快 | 之後卡片變多、打包變慢：改成每次執行用自己的快取資料夾 |
| 靜態圖的暫存檔寫在每次執行自己的暫存資料夾 | 寫在 `out` 旁邊時，同時畫同一張的兩次執行會搶同一個暫存檔 | 直接跑 `render.mjs`、`TMPDIR` 和 `out` 不在同一個磁碟時，改名會失敗；`pipeline` 一律把 `TMPDIR` 設在 `work/scenes` 裡 |
